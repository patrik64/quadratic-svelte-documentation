Unlike the other dialogs, this one is not a modal: it covers the entire window.
That fits what it does — it is the place you go when you are not working on the
current sheet but choosing a different one, so the grid behind it is irrelevant.

Three sources of files sit side by side: a blank grid, whatever is stored in
this browser, and the bundled examples. Reached from the `⌘O` command, from
three separate entries in
[CommandPalette.svelte](/docs/src/lib/components/CommandPalette.svelte), and
from the File menu.

## !!steps Examples described as data

The eight examples are declared with a display name, the file to fetch, a
one-line description and tags naming the features each demonstrates. The tag
union is closed, so a typo is a compile error rather than an unstyled chip —
each value has a matching CSS class.

Worth knowing when cross-referencing: only two of these files
(`formula_tour.grid` and `javascript.grid`) are produced by
[generate-examples.mjs](/docs/scripts/generate-examples.mjs); the rest are
committed artifacts in `static/examples/`.

```svelte ! FileMenu.svelte
<script lang="ts">
	interface Example {
		name: string;
		file: string;
		description: string;
		// !mark
		tags: ('Formulas' | 'Python' | 'JavaScript' | 'Data')[];
	}

	const EXAMPLES: Example[] = [
		{
			name: 'Formula tour (example)',
			file: 'formula_tour.grid',
			description: 'Aggregates, SUMIF/COUNTIF criteria, lookups, and date functions.',
			tags: ['Formulas']
		},
		{
			name: 'JavaScript (example)',
			file: 'javascript.grid',
			description: 'q.cells(), spilling a table, and a formula reading JS output.',
			tags: ['JavaScript', 'Formulas']
		},
	];
</script>
```

## !!steps Listing what is stored, forgivingly

The stored files come from `listStoredFiles` in
[gridFile.ts](/docs/src/lib/files/gridFile.ts), which returns metadata only —
names, sheet counts, timestamps — so opening this screen does not pull megabytes
of cell data out of IndexedDB.

The `catch` deliberately swallows the error and empties the list. If the store
is unavailable — a private browsing mode, a corrupted database — the right
outcome is a file screen showing the examples and a New grid button, not a
broken dialog. The user can still work; they simply have no saved files to
choose from.

Refreshing is a plain function rather than an effect, because it needs
re-running at specific moments: on mount, and after a duplicate or delete
changes the store.

```svelte ! FileMenu.svelte
<script lang="ts">
	async function refreshStored(): Promise<void> {
		try {
			stored = await listStoredFiles();
		} catch {
			// !mark
			stored = [];
		}
	}
	onMount(() => void refreshStored());
</script>
```

## !!steps Opening the file you already have open

`openStored` checks first whether the requested file is the current one, and if
so just closes the screen.

Without that guard, clicking the file you are already editing would run the
whole load path — replacing the sheets with their saved state, and silently
discarding anything typed since the last save. The short-circuit makes the
obvious gesture harmless.

```svelte ! FileMenu.svelte
<script lang="ts">
	async function openStored(id: string): Promise<void> {
		// !mark(1:4)
		if (id === app.fileId) {
			close();
			return;
		}
		await openStoredFile(id);
		close();
	}
</script>
```

## !!steps Delete that asks once, without a dialog

Deleting a file is irreversible, so it needs confirmation — but interrupting a
full-screen file browser with a modal would be heavy-handed.

Instead the button arms itself. The first click stores the id in
`confirmDeleteId` and returns; the markup then swaps that button's label to
`Delete?` and adds an `armed` class. Only a second click on the *same* button
proceeds.

Because the state is a single id rather than a boolean, arming one file
automatically disarms any other — clicking delete on file A and then on file B
leaves only B armed, which is the behavior you would want and comes for free
from the representation.

```svelte ! FileMenu.svelte
<script lang="ts">
	async function deleteStored(id: string): Promise<void> {
		// !mark(1:4)
		if (confirmDeleteId !== id) {
			confirmDeleteId = id; // first click arms, second click deletes
			return;
		}
		confirmDeleteId = '';
		await deleteStoredFileById(id);
		await refreshStored();
	}
</script>
```

## !!steps Timestamps at the resolution that matters

A file touched an hour ago is best identified by its time; one touched last
month by its date. Showing both always would be noise, so the threshold is a
day.

`toLocaleTimeString` and `toLocaleDateString` with no explicit locale use the
browser's, so the format matches what the user expects from the rest of their
system. The falsy check on `ms` covers a record with no timestamp, returning an
empty string rather than rendering the epoch.

```svelte ! FileMenu.svelte
<script lang="ts">
	function modifiedLabel(ms: number): string {
		if (!ms) return '';
		const days = (Date.now() - ms) / 86_400_000;
		// !mark(1:2)
		if (days < 1) return new Date(ms).toLocaleTimeString([], { hour: 'numeric', minute: '2-digit' });
		return new Date(ms).toLocaleDateString();
	}
</script>
```

## !!steps Fetching an example, one at a time

Examples are static assets, so opening one is a `fetch` against
`/examples/`, with the response text handed to `openFileFromJSON`.

`loading` holds the *filename* rather than a boolean, which lets it serve two
purposes: the markup shows an `Opening…` chip on the specific card being
fetched, while `disabled={loading !== ''}` greys out **all** the example
buttons. That prevents a second click starting a concurrent load that could
finish out of order and open the wrong file.

The explicit `res.ok` check matters because `fetch` does not reject on a 404 —
without it, a missing example would parse an HTML error page as JSON and produce
a confusing message instead of a clear one. `finally` clears the flag on both
paths, so a failure re-enables the buttons.

```svelte ! FileMenu.svelte
<script lang="ts">
	async function openExample(file: string, name: string): Promise<void> {
		loading = file;
		try {
			const res = await fetch(`/examples/${file}`);
			// !mark
			if (!res.ok) throw new Error(`${res.status} ${res.statusText}`);
			openFileFromJSON(await res.text(), name);
			close();
		} catch (err) {
			error = `Could not load ${name}: ${String(err)}`;
		} finally {
			// !mark
			loading = '';
		}
	}
</script>
```

## !!steps The stored file rows

Each row pairs a large open button with a small actions group. The open button
carries the name, an `open` badge when it is the current file, and a metadata
line pluralizing `sheet` correctly.

The delete button is **absent** for the currently open file, rather than
disabled — deleting the file you are editing has no coherent outcome, so the
affordance is simply not offered. Duplicate remains available for every row.

The armed state is visible in three places at once: the label becomes
`Delete?`, the `armed` class changes its appearance, and the `title` explains
what a second click will do — so the confirmation is legible whether the user is
reading, hovering, or just glancing.

```svelte ! FileMenu.svelte
							<span class="stored-actions">
								<button
									class="mini"
									title="Duplicate"
									onclick={() => void duplicateStored(f.id)}
								>⧉</button>
								{#if f.id !== app.fileId}
									<button
										class="mini danger"
										class:armed={confirmDeleteId === f.id}
										title={confirmDeleteId === f.id ? 'Click again to delete' : 'Delete'}
										onclick={() => void deleteStored(f.id)}
									>{confirmDeleteId === f.id ? 'Delete?' : '✕'}</button>
								{/if}
							</span>
```

## !!steps A hidden input, and covering the window

Opening a local file needs a real `input[type=file]`, kept in the markup with
`display: none` and clicked programmatically by the visible button. That is a
different approach from
[CommandPalette.svelte](/docs/src/lib/components/CommandPalette.svelte), which
constructs its input on demand — both work; this one is simpler to bind to,
that one avoids leaving an element in the tree.

The container is `position: fixed` with `inset: 0`, so it covers the viewport
entirely rather than floating over it like
[Modal.svelte](/docs/src/lib/components/Modal.svelte). `tabindex="-1"` makes
the div focusable so it can receive the keydown that handles Escape, and
`outline: none` suppresses the focus ring that would otherwise draw around the
whole screen.

```svelte ! FileMenu.svelte
	<input
		bind:this={fileInput}
		type="file"
		accept=".grid,.json"
		style="display: none"
		onchange={openLocal}
	/>
</div>

<style>
	.filemenu {
		position: fixed;
		inset: 0;
		background: var(--panel);
		z-index: 300;
		display: flex;
		flex-direction: column;
		outline: none;
	}
</style>
```

The three open paths all converge on
[state.svelte.ts](/docs/src/lib/state.svelte.ts): `newFile`, `openStoredFile`
and `openFileFromJSON`, which import through
[gridFile.ts](/docs/src/lib/files/gridFile.ts) and rebuild the sheets. Both
`openLocal` and `openExample` route through `openFileFromJSON`, so a bundled
example and a file from disk take exactly the same code path — the only
difference is where the text came from.

Errors from either are surfaced in a banner at the top of the screen rather than
thrown, since a malformed `.grid` file is a user-facing problem, not a bug.
