A JavaScript cell is a body of code whose **return value becomes the cell's
output**. This module is what makes that true: it compiles the user's source
into an async function, hands it an API for reading the sheet, captures
anything logged, and then translates whatever comes back — a number, an array,
a canvas — into something the grid can store.

Everything here runs on the main thread in the page's own realm. There is no
sandbox: a cell can reach `window` and `fetch`, which is what allows loading
chart libraries from a CDN.

<Scrollycoding>

## !!steps What a run produces

The result type is the contract with the rest of the app. `output_value` is the
single cell value, `array_output` the spilled block when the code returned a
collection, and `cells_accessed` the dependency list that
[updateCellAndDCells.ts](/docs/src/lib/core/updateCellAndDCells.ts) uses to
decide what recomputes when an input changes.

The three optional fields carry everything else a cell can produce: captured
logs, an error message, and a data URL when the code returned a canvas. Note
`success` is independent of `std_err` being present — a run can succeed while
having logged warnings.

```ts ! javascriptRunner.ts
export interface JavascriptRunResult {
	success: boolean;
	output_value: string | null;
	array_output?: ArrayOutput | null;
	// !mark
	cells_accessed: [number, number][];
	std_out?: string;
	std_err?: string;
	image_output?: string;
}
```

## !!steps Why static imports have to be rewritten

The cell body is compiled with `new AsyncFunction(...)`, and a static `import`
declaration inside a function body is a **syntax error** — imports are only
legal at the top level of a module. So user code that starts with
`import Chart from '...'` would fail to compile at all.

The fix is to rewrite each import into an equivalent `await import()`, which is
an expression and therefore legal anywhere. Two constraints shape the
implementation, both spelled out in the doc comment: it is deliberately
**line-based**, so an import spread across several lines is not recognized; and
every replacement occupies exactly one line, preserving the file's line count
so that error positions still map back to what the user wrote.

The simplest case is a bare side-effect import, handled first.

```ts ! javascriptRunner.ts
export function transformImports(code: string): string {
	const rewrite = (line: string): string => {
		// !mark(1:2)
		const bare = /^(\s*)import\s+(['"][^'"]+['"])\s*;?\s*$/.exec(line);
		if (bare) return `${bare[1]}await import(${bare[2]});`;
		const m = /^(\s*)import\s+([^'"]+?)\s+from\s+(['"][^'"]+['"])\s*;?\s*$/.exec(line);
		if (!m) return line;
		const [, indent, clause, spec] = m;
		let def: string | undefined;
		let rest = clause.trim();
		if (!'{*'.includes(rest[0])) {
			const dm = /^([A-Za-z_$][\w$]*)\s*(,\s*)?/.exec(rest);
			if (!dm) return line;
			def = dm[1];
			rest = rest.slice(dm[0].length).trim();
			if (rest !== '' && !dm[2]) return line;
		}
```

## !!steps Every import clause has its own destructuring

With the default binding peeled off, what remains is one of three shapes, and
each maps to a different destructuring of the module namespace object.

Named imports become object destructuring, with `as` renames converted to the
colon syntax destructuring already uses — `{ max as maximum }` becomes
`{ max: maximum }`. A default alongside them is folded in as `default: Name`,
since the default export is just a property called `default` on the namespace.

Namespace imports are the exception: `import * as d3` needs the whole object
bound to a name rather than destructured, so it emits a plain assignment, and a
default alongside it is pulled off in a second declarator. Anything the parser
does not recognize is returned unchanged, so a line that merely mentions the
word `import` is left alone.

```ts ! javascriptRunner.ts
		if (rest.startsWith('{') && rest.endsWith('}')) {
			// !mark(1:3)
			const inner = rest.slice(1, -1).replace(/\s+as\s+/g, ': ').trim();
			const parts = def ? `default: ${def}, ${inner}` : inner;
			return `${indent}const { ${parts} } = await import(${spec});`;
		}
		if (rest.startsWith('*')) {
			const ns = /^\*\s*as\s+([A-Za-z_$][\w$]*)$/.exec(rest);
			if (!ns) return line;
			return def
				? `${indent}const ${ns[1]} = await import(${spec}), ${def} = ${ns[1]}.default;`
				: `${indent}const ${ns[1]} = await import(${spec});`;
		}
		if (rest === '' && def) return `${indent}const { default: ${def} } = await import(${spec});`;
		return line;
	};
	return code.split('\n').map(rewrite).join('\n');
}
```

## !!steps Waiting for a chart to stop moving

Returning a canvas produces an image on the sheet, but grabbing its pixels
immediately would capture a half-drawn chart: libraries like Chart.js animate
their first render across several frames.

Rather than guessing a delay, this polls for stability. `sample` hashes the
pixel buffer — striding by 1021, a prime, so the samples spread across the
image instead of landing on one channel of every Nth pixel — and the loop waits
until two consecutive samples match, meaning nothing changed in the last
120ms. A 1600ms ceiling bounds the wait for a canvas that never settles, such
as a continuous animation.

```ts ! javascriptRunner.ts
	if (ctx && canvas.width > 0 && canvas.height > 0) {
		const sample = (): number => {
			const { data } = ctx.getImageData(0, 0, canvas.width, canvas.height);
			let h = 0;
			// !mark
			for (let i = 0; i < data.length; i += 1021) h = (h * 31 + data[i]) | 0;
			return h;
		};
		const started = performance.now();
		let prev = sample();
		// !mark(1:6)
		while (performance.now() - started < 1600) {
			await new Promise((r) => setTimeout(r, 120));
			const cur = sample();
			if (cur === prev) break;
			prev = cur;
		}
	}
```

## !!steps Reading the sheet, with types restored

Cell values are stored as strings, so handing them to JavaScript untouched
would make `q.cells('A1') * 2` produce `NaN` for a perfectly good number.
`coerce` restores the natural type: numeric strings become numbers, the three
spellings of each boolean become booleans, and everything else stays a string.
Empty cells become `undefined` rather than an empty string, so a missing value
is falsy in the obvious way.

Every read goes through `readCell`, which **records the coordinate** before
returning. That side effect is the dependency tracking — the cell doesn't
declare its inputs, they are discovered by watching what it actually reads.
`readRect` normalizes its corners with `Math.min`/`Math.max` so a range works
in any direction.

```ts ! javascriptRunner.ts
function coerce(raw: string | undefined): Scalar | undefined {
	if (raw === undefined || raw === '') return undefined;
	const n = Number(raw);
	if (!Number.isNaN(n) && raw.trim() !== '') return n;
	if (raw === 'TRUE' || raw === 'true' || raw === 'True') return true;
	if (raw === 'FALSE' || raw === 'false' || raw === 'False') return false;
	return raw;
}
// ...
	const readCell = (x: number, y: number): Scalar | undefined => {
		// !mark
		accessed.push([x, y]);
		return coerce(getCellValue(x, y));
	};
```

## !!steps One accessor, three shapes

`q.cells` accepts either a single reference or a range, parsing both through
[a1.ts](/docs/src/lib/core/a1.ts), and its return shape depends on the
geometry rather than on a flag.

A lone reference yields a scalar. A range collapses when it is one cell thick:
a single row returns a flat array, and so does a single column — via
`rows.map((r) => r[0])` — which means `q.cells('A1:A5')` gives you five values
you can `reduce` over directly, not five one-element arrays. Only a genuine
rectangle stays two-dimensional. A one-by-one range degenerates all the way
back to a scalar.

Alongside `q` the runner exposes `cell` and `cells` as coordinate-based
aliases, deliberately matching the API of
[pythonRunner.ts](/docs/src/lib/python/pythonRunner.ts) so the two languages
read alike.

```ts ! javascriptRunner.ts
	/** q.cells('A0') -> scalar; single row/col -> 1-D array; else 2-D. */
	const qCells = (a1: string) => {
		const parts = String(a1).split(':');
		const first = parseCellRef(parts[0]?.trim() ?? '');
		if (!first) throw new Error(`Invalid cell reference: '${a1}'`);
		if (parts.length === 1) return readCell(first.x, first.y);
		const second = parseCellRef(parts[1]?.trim() ?? '');
		if (!second) throw new Error(`Invalid cell reference: '${a1}'`);
		const rows = readRect(first.x, first.y, second.x, second.y);
		// !mark(1:3)
		if (rows.length === 1) return rows[0].length === 1 ? rows[0][0] : rows[0];
		if (rows[0].length === 1) return rows.map((r) => r[0]);
		return rows;
	};
```

## !!steps Compiling the cell and translating its errors

`AsyncFunction` is not a global, so it is reached through the prototype of an
async function expression. Constructing one with the API names as parameters is
what puts `q`, `cell`, `cells`, `pos` and `console` in scope for the user's
code — and because `console` is a *parameter*, the substituted
`capturedConsole` shadows the real one without any global patching, so logs are
collected rather than lost to devtools.

The failure path exists to fix line numbers. A thrown error's stack refers to
positions inside the generated function, which the `<anonymous>` pattern
extracts — and those are offset by the wrapper the constructor adds, so `- 2`
maps them back to the line the user actually wrote. This is the payoff for
`transformImports` preserving the line count: had rewriting changed it, every
reported position would be wrong.

```ts ! javascriptRunner.ts
	try {
		const AsyncFunction = Object.getPrototypeOf(async function () {}).constructor as new (
			...args: string[]
		) => (...fnArgs: unknown[]) => Promise<unknown>;
		// !mark(1:2)
		const fn = new AsyncFunction('q', 'cell', 'cells', 'pos', 'console', transformImports(code));
		result = await fn(q, cell, cells, q.pos, capturedConsole);
	} catch (e) {
		const err = e as Error;
		let message = err?.message ?? String(e);
		// map the stack's <anonymous> position back to a user line number
		const m = /<anonymous>:(\d+):(\d+)/.exec(err?.stack ?? '');
		// !mark
		if (m) message += ` at line ${Math.max(1, parseInt(m[1], 10) - 2)}:${m[2]}`;
		return {
			success: false,
			output_value: null,
			cells_accessed: accessed,
			std_out: logs.length ? logs.join('\n') : undefined,
			std_err: message
		};
	}
```

## !!steps A canvas becomes an image, or degrades gracefully

Before the return value is treated as data, it is checked for being a canvas.
If it is, the captured data URL goes into `image_output` and `output_value`
stays `null` — the cell holds a picture instead of a value, which is what
[PixiGrid.ts](/docs/src/lib/grid/pixi/PixiGrid.ts) turns into a sprite.

The `catch` is the considerate part: a canvas that cannot be read — a tainted
one, for instance — does not fail the cell. The problem is appended to the logs
as a warning and `result` is reset to `undefined`, so execution continues into
the normal conversion path and the cell simply ends up empty.

```ts ! javascriptRunner.ts
	// a returned canvas becomes an image on the sheet instead of a cell value
	if (isCanvas(result)) {
		try {
			const image = await captureCanvas(result);
			return {
				success: true,
				output_value: null,
				// !mark
				image_output: image,
				cells_accessed: accessed,
				std_out: logs.length ? logs.join('\n') : undefined
			};
		} catch (e) {
			// !mark(1:2)
			logs.push(`WARNING: could not capture canvas: ${(e as Error)?.message ?? e}`);
			result = undefined;
		}
	}
```

## !!steps Giving the return value a shape

`convertOutput` is where "arrays spill" becomes concrete, and the branch order
matters because the checks overlap.

An array of plain objects is recognized first, because it is also an array: the
keys of the first element become a header row and each object contributes a row
in that key order, which turns a list of records into a table without the user
formatting anything. An array of arrays is treated as rows, with short rows
padded to the widest so the block stays rectangular. A flat array spills down a
single column.

Every value passes through `sanitizeScalar`, which converts `Date` objects to
ISO strings and turns anything unrepresentable — including `NaN` and `Infinity`
— into `null`. That last case is caught for scalars and reported as a
targeted warning, as is the easy mistake of returning a `Promise` without
awaiting it.

```ts ! javascriptRunner.ts
	if (Array.isArray(result)) {
		if (result.length === 0) return { output_value: null };
		// array of plain objects: keys become a header row (modern behavior)
		if (
			typeof result[0] === 'object' &&
			result[0] !== null &&
			!Array.isArray(result[0]) &&
			!(result[0] instanceof Date)
		) {
			// !mark(1:5)
			const keys = Object.keys(result[0] as object);
			const rows: (Scalar | null)[][] = [keys];
			for (const item of result as Record<string, unknown>[]) {
				rows.push(keys.map((k) => sanitizeScalar(item?.[k])));
			}
			return { output_value: String(rows[1]?.[0] ?? ''), array_output: rows as ArrayOutput };
		}
		if (Array.isArray(result[0])) {
			// 2-D: pad short rows to the longest row
			const width = Math.max(...(result as unknown[][]).map((r) => r.length));
			const rows = (result as unknown[][]).map((r) => {
				const row = r.map(sanitizeScalar);
				while (row.length < width) row.push(null);
				return row;
			});
			return { output_value: String(rows[0]?.[0] ?? ''), array_output: rows as ArrayOutput };
		}
```
