Everything the TypeScript side knows about formulas passes through this file.
It loads the WebAssembly build of
[quadratic-core](/docs/quadratic-core/src/lib.rs), wraps its six exported
functions, and — for evaluation — hands the engine a callback so it can read the
sheet while it computes.

The engine is sheet-unaware by design, which shapes two of the wrappers here:
they mask cross-sheet references before delegating, a job handled by
[sheetRefs.ts](/docs/src/lib/formulas/sheetRefs.ts).

<Scrollycoding>

## !!steps Loading the wasm exactly once

`initPromise` memoizes initialization, so however many cells recalculate at
once, the module is fetched and instantiated a single time — every later caller
awaits the same promise.

The comment explains the explicit `module_or_path`. Left to its default,
wasm-bindgen guesses a URL relative to the JS file, which does not survive
Vite's dev server or its build hashing. Importing the binary with `?url` gives
Vite an asset it tracks and rewrites, and passing that through makes the path
correct in both modes. The trailing `hello()` is the core's own smoke call,
confirming the module really did instantiate.

```ts ! runFormula.ts
let initPromise: Promise<void> | undefined;

export function loadFormulaCore(): Promise<void> {
	if (!initPromise) {
		// explicit asset URL so Vite serves/bundles the wasm in dev and build
		// !mark
		initPromise = init({ module_or_path: wasmUrl }).then(() => hello());
	}
	return initPromise;
}
```

## !!steps Masking foreign references before rewriting

`adjustFormula` and `relocateFormula` both delegate the actual A1 rewriting to
Rust — `adjust_formula` for a row or column insertion, `relocate_formula` for a
copy, where relative refs follow and `$`-pinned ones do not.

Neither can be handed the raw formula. The engine's `CellRef` has no notion of
which sheet a reference belongs to, so a shift on *this* sheet would happily
rewrite the coordinates of a `Sheet2!A1` that should not move at all. Masking
replaces those references with inert placeholders first and restores them
afterwards.

The dynamic `import('./sheetRefs')` keeps that module out of the critical path
for callers that only evaluate.

```ts ! runFormula.ts
export async function adjustFormula(
	code: string,
	cell: { x: number; y: number },
	axis: 'x' | 'y',
	at: number,
	delta: number
): Promise<string> {
	await loadFormulaCore();
	const { maskSheetRefs } = await import('./sheetRefs');
	// !mark(1:2)
	const { masked, unmask } = maskSheetRefs(code);
	return unmask(adjust_formula(masked, cell.x, cell.y, axis === 'x', at, delta));
}
```

## !!steps Borrowing an editor protocol

Completions come from the core's LSP module, which returns items already shaped
for Monaco — labels, snippet insert text, documentation. The four `undefined`
arguments stand in for a text model, a position and the rest of the
`provideCompletionItems` signature; the comment records that the core ignores
them, since it returns the same full list regardless of context.

The result is cached and sorted once, alphabetically, rather than on every
keystroke. [CodeEditor.svelte](/docs/src/lib/components/CodeEditor.svelte)
filters that sorted list by prefix, so the ordering work happens a single time
per session.

```ts ! runFormula.ts
export async function getFormulaCompletions(): Promise<FormulaCompletion[]> {
	if (!completionsCache) {
		await loadFormulaCore();
		// !mark
		const list = provideCompletionItems(undefined, undefined, undefined, undefined) as {
			suggestions: FormulaCompletion[];
		};
		completionsCache = [...list.suggestions].sort((a, b) => a.label.localeCompare(b.label));
	}
	return completionsCache;
}

let docsCache: FormulaDoc[] | undefined;

/** Documentation for every formula function, from the Rust core. */
export async function getFormulaDocs(): Promise<FormulaDoc[]> {
	if (!docsCache) {
		await loadFormulaCore();
		docsCache = formula_docs() as FormulaDoc[];
	}
	return docsCache;
}
```

## !!steps A callback the engine reads the sheet through

Evaluation inverts the usual direction: rather than gathering inputs up front,
the JavaScript side passes a rectangle accessor and the **Rust engine calls
back into it** as evaluation reaches each reference. That is what lets the core
stay ignorant of how cells are stored.

The contract is spelled out in the comment and is easy to get subtly wrong.
Empty cells are *omitted* rather than returned as empty strings, because the
core reads `[0].value` and treats an empty array as "this cell is empty" — push
a blank entry and an empty cell would evaluate as an empty string instead.

The accessor is `async` because the original client's version fetched from a
database; here it resolves immediately, but the signature is preserved so the
vendored engine needs no change.

```ts ! runFormula.ts
	const gridAccessor = async (x0: number, y0: number, x1: number, y1: number) => {
		const cells: { x: number; y: number; value: string }[] = [];
		for (let y = y0; y <= y1; y++) {
			for (let x = x0; x <= x1; x++) {
				const value = getCellValue(x, y);
				// !mark
				if (value !== undefined && value !== '') cells.push({ x, y, value });
			}
		}
		return cells;
	};

	const output = await eval_formula(formula_code, pos.x, pos.y, gridAccessor);
	return output as RunFormulaResult;
}
```
