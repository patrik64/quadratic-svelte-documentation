Two suites covering the halves of
[gridFile.ts](/docs/src/lib/files/gridFile.ts) that can be tested without a
browser: the CSV parser, and the export/import pair.

The IndexedDB layer is absent, which is a reasonable line to draw — it would
need a fake implementation, and what it does is thin compared to the format
translation these tests pin down.

<Scrollycoding>

## !!steps The CSV cases that break naive splitting

Four tests, each aimed at a way `text.split(',')` would go wrong.

Quoted fields containing commas must stay one field, and doubled quotes must
collapse to a single literal quote — `"say ""hi"""` becoming `say "hi"` is the
case a hand-rolled parser most often gets wrong.

CRLF is tested together with a trailing newline, so one test covers both
consuming `\r\n` as a single break and not emitting a phantom final row.

```ts ! gridFile.test.ts
	it('handles quoted fields with commas and escaped quotes', () => {
		expect(parseCSV('"a,b",c')).toEqual([['a,b', 'c']]);
		// !mark
		expect(parseCSV('"say ""hi""",x')).toEqual([['say "hi"', 'x']]);
	});

	it('handles CRLF line endings and trailing newlines', () => {
		expect(parseCSV('a,b\r\n1,2\r\n')).toEqual([
			['a', 'b'],
			['1', '2']
		]);
	});
```

## !!steps Empty fields are data, empty rows are not

The sharpest CSV test, because it asserts two behaviors that sound
contradictory until you see them side by side.

The input has an empty field in the middle of a row, a completely blank line,
and a trailing empty field. The expectation keeps both empty *fields* — a blank
cell between commas is real, positional data — while the blank line vanishes
entirely.

That is exactly the distinction the parser's closing filter draws, and stating
it as a test means a later "simplification" that drops all empty strings would
fail immediately.

```ts ! gridFile.test.ts
	it('keeps empty fields but drops fully empty rows', () => {
		expect(parseCSV('a,,c\n\nx,y,')).toEqual([
			// !mark(1:2)
			['a', '', 'c'],
			['x', 'y', '']
		]);
	});
});
```

## !!steps A round trip through real JSON

The round-trip test builds a genuinely varied controller — a cell, a format
carrying both bold and a border, a resized column, then a second sheet with its
own cell, a rename and a color — so one assertion block covers every part of the
envelope.

The detail that makes it a real test is `JSON.parse(JSON.stringify(file))`.
Passing the exported object straight to the importer would let shared
references paper over a serialization bug; forcing it through JSON reproduces
what actually happens on disk, so anything not representable — a `Map`, an
`undefined`, a class instance — would surface here.

The assertions then check both sheets, including that sheet *identity* survives:
name and color, not just contents.

```ts ! gridFile.test.ts
		const file = exportGridFile(sc, 'My file', 'test-id');
		const sc2 = new SheetController();
		// !mark
		importGridFile(sc2, JSON.parse(JSON.stringify(file)) as GridFile);

		expect(sc2.sheets).toHaveLength(2);
		expect(sc2.sheets[0].getCell(0, 0)?.value).toBe('hello');
		expect(sc2.sheets[0].getFormat(0, 0)?.bold).toBe(true);
		expect(sc2.sheets[0].getFormat(0, 0)?.borders?.top).toBe('#000000');
		expect(sc2.sheets[0].gridOffsets.getColumnWidth(2)).toBe(150);
		expect(sc2.sheets[1].name).toBe('Data');
		expect(sc2.sheets[1].color).toBe('#ff0000');
		expect(sc2.sheets[1].getCell(1, 1)?.value).toBe('other');
```

## !!steps Both legacy shapes, and a real failure

The legacy test constructs a pre-multi-sheet file — content at the top level,
no `sheets` array — and asserts it loads as exactly one sheet. That is the shape
detection rather than a version check, so it would still work on a file with no
version field at all.

The border test is the most detailed of the three, and its third fixture entry
is the interesting one: a border record with neither edge, commented in the
source as ignored, asserted by expecting `getFormat(5, 6)` to be `undefined`.
Checking that *no format was created* is stronger than checking the borders are
empty — it proves the skip happens before any format is materialized.

The suite ends by confirming a file with no recoverable content throws rather
than importing as an empty sheet, matching on the message fragment so the
wording can change.

```ts ! gridFile.test.ts
					borders: [
						{ x: 1, y: 2, horizontal: {} },
						{ x: 3, y: 4, vertical: { color: '#ff0000' } },
						{ x: 5, y: 6 } // no edges → ignored
					]
// ...
		const sc = new SheetController();
		importGridFile(sc, file);
		// !mark(1:3)
		expect(sc.sheet.getFormat(1, 2)?.borders).toEqual({ top: '#000000' });
		expect(sc.sheet.getFormat(3, 4)?.borders).toEqual({ left: '#ff0000' });
		expect(sc.sheet.getFormat(5, 6)).toBeUndefined();
	});

	it('throws on files with no sheet content', () => {
		expect(() => importGridFile(new SheetController(), {} as GridFile)).toThrow(
			'no sheets'
		);
	});
```

</Scrollycoding>

The border assertions are worth reading against the import code: the fixture's
`horizontal: {}` — present but with no color — comes back as `#000000`,
confirming the default, while `vertical` maps to `left`. Both encode the
orientation-versus-edge naming that would otherwise be easy to invert.

Run with `pnpm test`. Untested here: the whole IndexedDB layer, the two
migration paths in `loadCurrentFile`, and `downloadGridFile`, all of which need
browser APIs.
