This is the engine that actually paints the spreadsheet — a port of Quadratic's
`gridGL/pixiApp` onto pixi.js v8 and `pixi-viewport`. It owns a WebGL canvas, a
handful of long-lived layers, and a per-frame update that decides whether
anything needs to be redrawn at all.

The three ideas that make it fast are stated in its own header comment: display
objects **persist between frames**, panning and zooming are a **pure viewport
transform** (nothing is re-laid-out), and each layer redraws only when its
**dirty flag** is set. The class is deliberately UI-framework-agnostic: it reads
the sheet and the UI state through two callbacks passed to the constructor, so
[GridCanvas.svelte](/docs/src/lib/components/GridCanvas.svelte) can drive it
with Svelte runes without the renderer knowing Svelte exists.

## !!steps Dirty flags and persistent layers

Every layer is created **once**, in the field initializers, and lives for the
lifetime of the engine — a `Graphics` per drawing concern plus two `Container`s
for objects that come and go. Redrawing a layer means `clear()` and re-issuing
its commands, never rebuilding the scene graph.

The three booleans are the whole scheduling protocol. `dirtyCells` means the
sheet's content changed, `dirtyViewport` means the camera moved, `dirtyCursor`
means only the selection moved — the cheapest of the three. `labelCache` maps a
cell key to an already-rasterized `Text`, and `imageTextures` holds chart
textures keyed by a cheap signature so the same PNG is uploaded to the GPU once.

```ts ! PixiGrid.ts
export class PixiGrid {
	app = new Application();
	viewport!: Viewport;
	headings!: GridHeadings;

	// !mark(1:3)
	dirtyViewport = true;
	dirtyCells = true;
	dirtyCursor = true;

	/** Fires whenever the pixi viewport moves/zooms (drag, wheel, decelerate). */
	onViewportChanged: (x: number, y: number, scale: number) => void = () => {};

	private fills = new Graphics();
	private gridLines = new Graphics();
	private axes = new Graphics();
	private borders = new Graphics();
	private outlines = new Graphics();
	private labelLayer = new Container();
	private imageLayer = new Container();
	private selectionGfx = new Graphics();
	// !mark
	private labelCache = new Map<string, CachedLabel>();
	// canvas outputs (charts), keyed by a cheap signature of the data URL
	private imageTextures = new Map<string, Texture | 'loading'>();
	private destroyed = false;

	constructor(
		private getSheet: () => Sheet,
		private getState: () => GridUIState
	) {}
}
```

## !!steps Booting the application and the viewport

`init` is async because pixi v8 initializes the renderer asynchronously; the
`destroyed` check right after the `await` handles a component that unmounted
while the GPU context was still coming up. `resolution` plus `autoDensity` make
the canvas render at device pixel density so text stays crisp on retina
displays.

Then `pixi-viewport` takes over input. The plugin chain is the entire pan/zoom
story: `drag` only pans while Space is held (a spreadsheet still needs plain
drag for selection), `decelerate` adds inertia, `pinch` and `wheel` handle
trackpads, and `clampZoom` bounds the scale to `0.1 … 10`. Because zoom is a
transform on one container, zooming costs nothing per cell.

```ts ! PixiGrid.ts
	async init(container: HTMLElement): Promise<void> {
		await this.app.init({
			background: '#ffffff',
			antialias: true,
			// !mark(1:2)
			resolution: window.devicePixelRatio || 1,
			autoDensity: true,
			width: container.clientWidth || 800,
			height: container.clientHeight || 600,
			preference: 'webgl'
		});
		if (this.destroyed) return;
		this.app.canvas.classList.add('grid-canvas');
		container.appendChild(this.app.canvas);

		this.viewport = new Viewport({
			events: this.app.renderer.events,
			screenWidth: container.clientWidth,
			screenHeight: container.clientHeight,
			ticker: this.app.ticker,
			passiveWheel: false,
			disableOnContextMenu: true
		});
		this.viewport
			.drag({ pressDrag: true, keyToPress: ['Space'] })
			.decelerate()
			.pinch()
			.wheel({ trackpadPinch: true, wheelZoom: false, percent: 1.5 })
			.clampZoom({ minScale: 0.1, maxScale: 10 });
		// ...
	}
```

## !!steps Layer order and the frame ticker

One `addChild` call fixes the painter's-algorithm order for the whole app:
fills at the bottom, then gridlines, then axes, then borders (above gridlines so
a cell border paints over them), code outlines, text labels, chart images, and
the selection overlay on top of everything.

The headings are added to the **stage**, not the viewport — they must stay
pinned to the screen edges while the world scrolls underneath, so
[GridHeadings.ts](/docs/src/lib/grid/pixi/GridHeadings.ts) draws in screen space
and reads the viewport itself. Finally `handleMoved` closes the loop with the
outside world: any viewport movement marks the viewport dirty *and* reports the
new camera through `onViewportChanged`, which the Svelte layer stores in
`app.viewport` so DOM overlays can follow the grid.

```ts ! PixiGrid.ts
		this.viewport.addChild(
			this.fills,
			this.gridLines,
			this.axes,
			this.borders, // above gridlines so cell borders paint over them
			this.outlines,
			this.labelLayer,
			this.imageLayer, // charts cover cell text beneath them
			this.selectionGfx
		);
		this.app.stage.addChild(this.viewport);

		// !mark(1:2)
		this.headings = new GridHeadings(this.getSheet, () => this.viewport);
		this.app.stage.addChild(this.headings.container);

		this.viewport.on('moved', this.handleMoved, this);
		this.viewport.on('zoomed', this.handleMoved, this);
		// ...
		this.app.ticker.add(this.update, this);
	}

	private handleMoved(): void {
		this.dirtyViewport = true;
		this.onViewportChanged(this.viewport.left, this.viewport.top, this.viewport.scale.x);
	}
```

## !!steps The dirty flag frame loop

`update` runs on every pixi tick and its job is mostly to decide *not* to work.
When `dirtyCells` is set the content changed, so the entire label cache is
destroyed and `lastRange` is poisoned with `NaN` — that forces the cell pass to
re-run and every label to re-rasterize with fresh text and styles.

The interesting condition is the second one: while panning, every `moved` event
sets `dirtyViewport`, but the cell layers are only redrawn when the *visible
cell range* actually changed. Scrolling half a cell moves the camera without changing
which cells are on screen, so the labels simply ride along with the viewport
transform and nothing is rebuilt. The final `else if` is the cheap path — a
cursor move repaints only the selection graphics and the headings, leaving
fills, gridlines and thousands of text objects untouched.

```ts ! PixiGrid.ts
	private update(): void {
		if (!this.viewport) return;
		const state = this.getState();
		if (this.dirtyCells) {
			// content changed: throw away label cache so text/styles refresh
			for (const cached of this.labelCache.values()) cached.text.destroy();
			this.labelCache.clear();
			this.labelLayer.removeChildren();
			this.lastRange = { colStart: NaN, colEnd: NaN, rowStart: NaN, rowEnd: NaN };
		}
		const range = this.visibleRange();
		const rangeChanged =
			range.colStart !== this.lastRange.colStart ||
			range.colEnd !== this.lastRange.colEnd ||
			range.rowStart !== this.lastRange.rowStart ||
			range.rowEnd !== this.lastRange.rowEnd;

		// cell layers only when content or the visible cell range changed
		// !mark
		if (this.dirtyCells || this.labelsPending || (this.dirtyViewport && rangeChanged)) {
			this.drawCells(state, range);
			this.lastRange = range;
		}
		if (this.dirtyCells || this.dirtyViewport) {
			this.drawGridLines(state);
			this.drawCursor(state);
			this.headings.draw(this.headingsState(state));
			this.dirtyCells = false;
			this.dirtyViewport = false;
			this.dirtyCursor = false;
			// !mark
		} else if (this.dirtyCursor) {
			this.drawCursor(state);
			this.headings.draw(this.headingsState(state));
			this.dirtyCursor = false;
		}
	}
```

## !!steps Culling to the visible range

The sheet is infinite, so every drawing pass first asks *which cells are on
screen*. `visibleRange` converts the viewport's world rectangle into cell
indices with [GridOffsets.ts](/docs/src/lib/core/GridOffsets.ts) — the same
coordinate mapping the mouse handlers and the cell editor use — and pads the
result by `CULL_MARGIN_CELLS` so a few rows and columns just outside the frame
are already drawn when they scroll in.

`drawGridLines` shows the pattern: it iterates only `colStart … colEnd + 1`, but
extends each line 100 world units past the viewport edges so no gap is visible
at the border. `pixelLine: true` keeps lines exactly one device pixel wide at
any zoom, and `gridLineAlpha` (from [colors.ts](/docs/src/lib/grid/colors.ts))
fades the grid out below `0.6` scale — at that point the lines would otherwise
merge into a solid gray field.

```ts ! PixiGrid.ts
const CULL_MARGIN_CELLS = 3;
// ...
	private visibleRange(): { colStart: number; colEnd: number; rowStart: number; rowEnd: number } {
		const offsets = this.getSheet().gridOffsets;
		const v = this.viewport;
		return {
			// !mark(1:4)
			colStart: offsets.getColumnIndex(v.left) - CULL_MARGIN_CELLS,
			colEnd: offsets.getColumnIndex(v.left + v.screenWidth / v.scale.x) + CULL_MARGIN_CELLS,
			rowStart: offsets.getRowIndex(v.top) - CULL_MARGIN_CELLS,
			rowEnd: offsets.getRowIndex(v.top + v.screenHeight / v.scale.y) + CULL_MARGIN_CELLS
		};
	}

	private drawGridLines(state: GridUIState): void {
		// ...
		const { colStart, colEnd, rowStart, rowEnd } = this.visibleRange();
		// ...
		if (state.showGridLines && !state.presentationMode) {
			for (let x = colStart; x <= colEnd + 1; x++) {
				const wx = offsets.getColumnX(x);
				g.moveTo(wx, wTop).lineTo(wx, wBottom);
			}
			// ...
			// modern look: gridlines fade out as you zoom out
			g.stroke({ color: colors.gridLines, alpha: 0.2 * gridLineAlpha(v.scale.x), pixelLine: true });
		}
	}
```

## !!steps Fills and borders from formats

`drawCells` is the heart of the renderer. It opens by resetting the per-frame
label budget, then repaints the fill and border layers by walking every format
in the sheet and skipping the ones outside the visible range. Formats are sparse
— only cells the user actually styled have one — so this loop is short even on
large sheets. Each rectangle comes from `getCellRect`, so a resized column moves
its fill and its text together with no extra bookkeeping.

The cell query that follows is subtler: it starts **40 columns to the left** of
the visible range. Unwrapped text overflows into empty neighbors, so a long
label anchored far off-screen can still be partly visible; without that margin
it would pop in only when its own cell scrolled into view.

```ts ! PixiGrid.ts
const MAX_VISIBLE_LABELS = 6000;
// Text rasterization is the expensive step; cap creations per frame and
// stream the rest in on subsequent frames so panning never blocks
const LABEL_BUDGET_PER_FRAME = 250;
// ...
	private drawCells(state: GridUIState, range: ReturnType<PixiGrid['visibleRange']>): void {
		const offsets = this.getSheet().gridOffsets;
		const { colStart, colEnd, rowStart, rowEnd } = range;
		this.labelsPending = false;
		let creationBudget = LABEL_BUDGET_PER_FRAME;

		// fills + borders from formats
		const fills = this.fills;
		fills.clear();
		const borders = this.borders;
		borders.clear();
		for (const format of this.getSheet().getAllFormats()) {
			if (!format.fillColor && !format.borders) continue;
			// !mark(1:2)
			if (format.x < colStart || format.x > colEnd || format.y < rowStart || format.y > rowEnd)
				continue;
			const r = offsets.getCellRect(format.x, format.y);
			if (format.fillColor) fills.rect(r.x, r.y, r.w, r.h).fill(format.fillColor);
			const b = format.borders;
			if (b) {
				if (b.top)
					borders.moveTo(r.x, r.y).lineTo(r.x + r.w, r.y).stroke({ color: b.top, pixelLine: true });
				// ...
			}
		}
		// ...
		const cells = this.getSheet().getCellsInRect({
			left: colStart - 40, // long text from offscreen cells can overflow in
			top: rowStart,
			right: colEnd,
			bottom: rowEnd
		});
		// ...
	}
```

## !!steps The label cache signature

Rasterizing text is by far the most expensive thing a canvas spreadsheet does,
so each label is keyed by its cell and tagged with a `sig` string that encodes
everything its bitmap depends on: the formatted text (from
[cellTextFormatter.ts](/docs/src/lib/core/cellTextFormatter.ts)), bold/italic,
color, alignment and wrapping mode. If the signature still matches, the existing
`Text` object is reused untouched; if it differs, the old one is destroyed and
rebuilt. For wrapped cells the cell's size joins the signature, because
line-breaking depends on the column width — resizing that column must
re-rasterize.

The two guards above it are the throughput limits. `MAX_VISIBLE_LABELS` caps how
many labels a single frame will consider, and `creationBudget` caps how many new
`Text` objects may be *created* per frame; when it runs out the loop sets
`labelsPending` and bails, and the frame loop calls `drawCells` again next tick
to stream in the rest. That is what keeps a fast pan across dense data from
blocking on hundreds of glyph rasterizations in one frame.

```ts ! PixiGrid.ts
			if (labelCount >= MAX_VISIBLE_LABELS) continue;
			const format = this.getSheet().getFormat(cell.x, cell.y);
			const displayText = formatCellValue(cell, format);
			if (displayText === '') continue;
			labelCount++;

			const key = coordKey(cell.x, cell.y);
			const align = format?.alignment ?? 'left';
			const wrapping = format?.wrapping;
			const r = offsets.getCellRect(cell.x, cell.y);
			// light fill colors keep dark text even in the dark theme
			const fontColor =
				format?.textColor ??
				(format?.fillColor && isLightColor(format.fillColor)
					? '#000000'
					: colors.cellFontColor);
			// wrapped layout depends on the cell's size, so resizes re-rasterize
			const sizeSig = wrapping === 'wrap' ? `|${r.w}x${r.h}` : '';
			// !mark
			const sig = `${displayText}|${format?.bold ? 'b' : ''}${format?.italic ? 'i' : ''}|${fontColor}|${align}|${wrapping ?? ''}${sizeSig}`;
			let cached = this.labelCache.get(key);
			if (cached && cached.sig !== sig) {
				cached.text.destroy();
				this.labelLayer.removeChild(cached.text);
				cached = undefined;
				this.labelCache.delete(key);
			}
			// !mark(1:4)
			if (!cached && creationBudget <= 0) {
				this.labelsPending = true; // stream the rest in on the next frame
				continue;
			}
```

## !!steps Rasterizing a label once

Only a cache miss reaches this block. Wrapped cells are pre-wrapped through
`measureWrapped` from
[measureText.ts](/docs/src/lib/grid/pixi/measureText.ts) — the same measurer
pixi uses internally, so the line count matches what will actually render — and
lines beyond the row height are dropped rather than drawn and clipped.

The `resolution` of at least 2 is what keeps glyphs sharp when the user zooms
in, since a `Text` is a bitmap and scaling it up would otherwise blur. Overflow
is handled by measuring against `availableExtent`, which walks up to 40 columns
in the direction of the alignment and adds their widths until it hits a
non-empty neighbor; text longer than that is truncated by a proportional
character estimate instead of re-measuring repeatedly. Alignment and vertical
centering are plain position math on the cell rect, and only then does the label
enter the layer and the cache.

```ts ! PixiGrid.ts
			if (!cached) {
				creationBudget--;
				let labelText = displayText;
				if (wrapping === 'wrap') {
					// pre-wrap into lines, keeping only what fits the row height
					const m = measureWrapped(displayText, r.w, {
						bold: format?.bold,
						italic: format?.italic
					});
					const maxLines = Math.max(1, Math.floor((r.h - 2) / m.lineHeight));
					labelText = m.lines.slice(0, maxLines).join('\n');
				}
				const text = new Text({
					text: labelText,
					style: {
						fontFamily: 'OpenSans, sans-serif',
						fontSize: FONT_SIZE,
						fill: fontColor,
						// ...
					},
					// !mark
					resolution: Math.max(2, window.devicePixelRatio || 1)
				});

				// overflow: truncate at the next non-empty cell (clip/wrap stay in cell)
				const available = this.availableExtent(cell.x, cell.y, r.w, align, wrapping);
				if (wrapping !== 'wrap' && text.width > available && displayText.length > 1) {
					const keep = Math.max(1, Math.floor((displayText.length * available) / text.width));
					text.text = displayText.slice(0, keep);
				}

				if (align === 'right') text.position.set(r.x + r.w - CELL_TEXT_MARGIN_LEFT - text.width, 0);
				else if (align === 'center') text.position.set(r.x + (r.w - text.width) / 2, 0);
				else text.position.set(r.x + CELL_TEXT_MARGIN_LEFT, 0);
				text.y = r.y + (r.h - text.height) / 2 + 0.5;

				// !mark(1:2)
				this.labelLayer.addChild(text);
				this.labelCache.set(key, { text, sig });
			}
```

## !!steps Dropping labels that scrolled away

A cache that only grows would eventually hold a `Text` — and a GPU texture — for
every cell ever visited. So the pass ends by sweeping the cache and destroying
anything outside the range it just drew. The keys are `"x,y"` strings from
`coordKey`, parsed back with a single `indexOf` rather than a `split`, since
this runs over the whole cache every frame that redraws cells.

`KEEP_MARGIN` is the reason panning feels smooth: labels are kept for ten cells
past the culling boundary, so nudging the view back and forth across an edge
reuses the same objects instead of destroying and re-rasterizing them on every
direction change. The same eviction idea applies to chart textures in
`drawImages`, which destroys the `Texture` of any image that left the view.

```ts ! PixiGrid.ts
		// drop labels that scrolled out of range (with margin so near-edge
		// labels survive small pans without re-rasterizing)
		// !mark
		const KEEP_MARGIN = 10;
		for (const [key, cached] of this.labelCache) {
			const comma = key.indexOf(',');
			const x = Number(key.slice(0, comma));
			const y = Number(key.slice(comma + 1));
			if (
				x < colStart - 40 - KEEP_MARGIN ||
				x > colEnd + KEEP_MARGIN ||
				y < rowStart - KEEP_MARGIN ||
				y > rowEnd + KEEP_MARGIN
			) {
				cached.text.destroy();
				this.labelLayer.removeChild(cached.text);
				this.labelCache.delete(key);
			}
		}
```

## !!steps Cursor and selection overlays

`drawCursor` repaints one `Graphics` — the topmost layer — from the UI state
snapshot. A multi-cursor becomes a translucent rectangle spanning the normalized
selection (`selectionRange` sorts origin and terminal so dragging in any
direction works), and the cursor cell gets an outline drawn as an open path with
a small gap in the bottom-right corner, leaving room for the fill handle.

Note the divisions by `scale`: line widths and the gap are specified as
`1.5 / scale` and `5 / scale` so that after the viewport's transform they land
at a constant number of screen pixels. Without that, the cursor outline would
grow into a thick band when zoomed in and vanish when zoomed out. The rest of
the method draws the fill-handle square, the fill-drag preview, the formula
pointing-mode preview and the code-editor cell highlight — all from optional
fields on the state snapshot, all in the same single `Graphics`.

```ts ! PixiGrid.ts
	private drawCursor(state: GridUIState): void {
		const g = this.selectionGfx;
		g.clear();
		const offsets = this.getSheet().gridOffsets;
		const scale = this.viewport.scale.x;

		// multi-select
		if (state.multiCursor) {
			const sel = this.selectionRange(state);
			const left = offsets.getColumnX(sel.x0);
			const top = offsets.getRowY(sel.y0);
			const right = offsets.getColumnX(sel.x1) + offsets.getColumnWidth(sel.x1);
			const bottom = offsets.getRowY(sel.y1) + offsets.getRowHeight(sel.y1);
			g.rect(left, top, right - left, bottom - top)
				.fill({ color: colors.cursorCell, alpha: 0.1 })
				.stroke({ color: colors.cursorCell, pixelLine: true });
		}
		// ...
		const r = offsets.getCellRect(state.cursorPosition.x, state.cursorPosition.y);
		if (!editorOnCursor) {
			// !mark
			const lw = 1.5 / scale;
			if (state.multiCursor) {
				g.rect(r.x, r.y, r.w, r.h).stroke({ color: colors.cursorCell, width: lw });
			} else {
				// !mark
				const gap = 5 / scale;
				g.moveTo(r.x + r.w - gap, r.y + r.h)
					.lineTo(r.x, r.y + r.h)
					.lineTo(r.x, r.y)
					.lineTo(r.x + r.w, r.y)
					.lineTo(r.x + r.w, r.y + r.h - gap)
					.stroke({ color: colors.cursorCell, width: lw });
			}
		}
		// ...
	}
```

The engine is created and owned by
[GridCanvas.svelte](/docs/src/lib/components/GridCanvas.svelte), which passes in
the sheet getter and a `snapshot()` of the UI state, sets the dirty flags from
Svelte effects, and mirrors the camera both ways: `onViewportChanged` writes
`app.viewport` in [state.svelte.ts](/docs/src/lib/state.svelte.ts), while
`applyViewport` pushes external changes (zoom buttons, go-to, keyboard
scrolling) back into the viewport — guarded by an epsilon comparison so the two
directions cannot ping-pong. That component also drives `resize` from a
`ResizeObserver`.

Everything geometric goes through
[GridOffsets.ts](/docs/src/lib/core/GridOffsets.ts), so cells, gridlines,
cursors and the DOM-based [CellInput.svelte](/docs/src/lib/components/CellInput.svelte)
all agree on where a cell is. Screen-space chrome lives in
[GridHeadings.ts](/docs/src/lib/grid/pixi/GridHeadings.ts), text metrics in
[measureText.ts](/docs/src/lib/grid/pixi/measureText.ts), and the palette —
including the theme switch that invalidates every cached label — in
[colors.ts](/docs/src/lib/grid/colors.ts).
