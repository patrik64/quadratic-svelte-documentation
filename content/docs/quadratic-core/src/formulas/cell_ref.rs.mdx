When a formula says `A1`, it does not mean a fixed place on the grid — it means
an offset from the cell the formula lives in, so that copying the formula
elsewhere moves what it points at. Writing `$A$1` instead pins it. This file is
where that distinction lives: references are stored as `Relative` or `Absolute`
per axis, and only turned into concrete grid coordinates at evaluation time,
against the position of the cell doing the evaluating.

It is the Rust counterpart to the app's own A1 helpers in
[a1.ts](/docs/src/lib/core/a1.ts), and shares their conventions: an infinite
grid centred on the origin, with negative columns and rows written with a
lowercase `n` prefix. What it adds on top is Excel's `$` anchoring.

## !!steps Four shapes of a reference

A formula can name a single cell (`A1`), a rectangle (`A1:C5`), a span of whole
rows, or a span of whole columns — so `RangeRef` has one variant for each. The
row and column ranges hold bare `CellRefCoord` values because only one axis is
constrained; the other is unbounded.

`Display` here is the *internal* form, not what a user types: an `R` or `C`
tag in front of each coordinate, with the coordinate itself printed by
`CellRefCoord`, whose own `Display` appears further down. The next step covers
A1 rendering.

```rust ! cell_ref.rs
#[derive(Serialize, Deserialize, Debug, Copy, Clone, PartialEq, Eq, Hash)]
pub enum RangeRef {
    RowRange(CellRefCoord, CellRefCoord),
    ColRange(CellRefCoord, CellRefCoord),
    CellRange(CellRef, CellRef),
    Cell(CellRef),
}
impl fmt::Display for RangeRef {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            RangeRef::RowRange(start, end) => write!(f, "R{start}:R{end}"),
            RangeRef::ColRange(start, end) => write!(f, "C{start}:C{end}"),
            RangeRef::CellRange(start, end) => write!(f, "{start}:{end}"),
            RangeRef::Cell(cell) => write!(f, "{cell}"),
        }
    }
}
```

## !!steps Rendering back to A1

`a1_string` is the inverse of parsing, and it needs a `base` — the cell the
reference is written *in* — because a relative coordinate has no meaning on its
own. Feeding it a different base than the one it was parsed with is exactly how
references get rewritten: [lib.rs](/docs/quadratic-core/src/lib.rs) calls
`adjusted.a1_string(new_base)` in `adjust_formula` and `relocate_formula` to
splice updated text back into the formula string when rows/columns are inserted
or a formula is copied.

```rust ! cell_ref.rs
impl RangeRef {
    /// Returns the human-friendly string representing this range reference in
    /// A1-style notation.
    pub fn a1_string(self, base: Pos) -> String {
        match self {
            RangeRef::RowRange(start, end) => {
                format!("{}:{}", start.row_string(base.y), end.row_string(base.y))
            }
            RangeRef::ColRange(start, end) => {
                format!("{}:{}", start.col_string(base.x), end.col_string(base.x))
            }
            RangeRef::CellRange(start, end) => {
                // !mark
                format!("{}:{}", start.a1_string(base), end.a1_string(base))
            }
            RangeRef::Cell(cell) => cell.a1_string(base),
        }
    }
}
```

## !!steps A cell is two independent coordinates

`CellRef` is just an x and a y, each of which carries its own relative/absolute
flag — which is what makes mixed references like `$A1` representable.
`absolute` builds a reference pinned to a known `Pos`, for the cases where
coordinates arrive as numbers rather than as source text — it is how
`array_mapped_get_cell` in
[ctx.rs](/docs/quadratic-core/src/formulas/ctx.rs) turns evaluated x and y
arguments into a reference.

`resolve_from` is the whole point of the type: hand it the evaluating cell's
position and each axis resolves independently to a plain `Pos`.

```rust ! cell_ref.rs
#[derive(Serialize, Deserialize, Debug, Copy, Clone, PartialEq, Eq, Hash)]
pub struct CellRef {
    pub x: CellRefCoord,
    pub y: CellRefCoord,
}
impl fmt::Display for CellRef {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        let Self { x, y } = self;
        write!(f, "R{y}C{x}")
    }
}
impl CellRef {
    /// Constructs an absolute cell reference.
    pub fn absolute(pos: Pos) -> Self {
        Self {
            x: CellRefCoord::Absolute(pos.x),
            y: CellRefCoord::Absolute(pos.y),
        }
    }

    /// Resolves the reference to a absolute coordinates, given the cell
    /// coordinate where evaluation is taking place.
    pub fn resolve_from(self, base: Pos) -> Pos {
        Pos {
            // !mark(1:2)
            x: self.x.resolve_from(base.x),
            y: self.y.resolve_from(base.y),
        }
    }
```

## !!steps The A1 regex, annotated in place

The regex is built once behind `lazy_static!`, and the source keeps an ASCII
diagram of what each group captures. Five groups: a `$` before the column, the
column name, a `$` before the row, an `n` marking a negative row, and the row
digits. Note that the column's own negative marker lives *inside* group 2
(`n?[A-Z]+`) — `column_from_name` in
[util.rs](/docs/quadratic-core/src/util.rs) strips it there.

Column letters must be uppercase, so this parser is stricter than the app-side
regex in [a1.ts](/docs/src/lib/core/a1.ts); by the time it runs, the
[lexer](/docs/quadratic-core/src/formulas/lexer.rs) has already isolated the
token.

```rust ! cell_ref.rs
    /// Parses an A1-style cell reference relative to a given location.
    pub fn parse_a1(s: &str, base: Pos) -> Option<CellRef> {
        lazy_static! {
            /// ^(\$?)(n?[A-Z]+)(\$?)(n?)(\d+)$
            /// ^                             $     match full string
            ///  (\$?)                              group 1: optional `$`
            ///       (n?[A-Z]+)                    group 2: column name
            ///                 (\$?)               group 3: optional `$`
            ///                      (n?)           group 4: optional `n`
            ///                          (\d+)      group 5: row number
            // !mark
            pub static ref A1_CELL_REFERENCE_REGEX: Regex =
                Regex::new(r#"^(\$?)(n?[A-Z]+)(\$?)(n?)(\d+)$"#).unwrap();
        }

        let captures = A1_CELL_REFERENCE_REGEX.captures(s)?;

        let column_is_absolute = !captures[1].is_empty();
        let column_name = &captures[2];
        let row_is_absolute = !captures[3].is_empty();
        let row_is_negative = !captures[4].is_empty();
        let row_number = &captures[5];
```

## !!steps Absolute keeps the number, relative keeps the offset

This is the conversion that makes `$` meaningful. Both branches start from the
same resolved column and row, but an absolute coordinate stores the number
itself, while a relative one stores the *delta* from the base. Copy the formula
one row down and the relative delta still points one row down; the absolute
number does not move.

Everything is fallible and returns `Option`: an out-of-range column name or a
row number that overflows `i64` yields `None`, which the parser reports as
`BadCellReference` from
[errors.rs](/docs/quadratic-core/src/formulas/errors.rs).

```rust ! cell_ref.rs
        let col = crate::util::column_from_name(column_name)?;
        let mut row = row_number.parse::<i64>().ok()?;
        if row_is_negative {
            row = -row;
        }

        let col_ref = if column_is_absolute {
            CellRefCoord::Absolute(col)
        } else {
            // !mark
            CellRefCoord::Relative(col - base.x)
        };
        let row_ref = if row_is_absolute {
            CellRefCoord::Absolute(row)
        } else {
            CellRefCoord::Relative(row - base.y)
        };

        Some(CellRef {
            x: col_ref,
            y: row_ref,
        })
    }
}
```

## !!steps One coordinate, two flavours

`CellRefCoord` is the two-variant enum everything above is built from, and both
variants hold an `i64` — a relative delta or an absolute position. The default
is `Relative(0)`, i.e. "this same row/column", matching the unanchored A1 style
users write most often.

`Display` and `FromStr` use a bracket notation for relative values: `[3]` means
three away, a bare number means absolute. `from_str` tries the bracket form
first with an immediately-invoked closure standing in for a `try` block, then
falls back to a plain integer parse. Note the asymmetry — `Display` writes
negative absolutes with an `n` prefix, while `from_str` goes through
`i64::from_str`, which expects a leading `-`.

```rust ! cell_ref.rs
#[derive(Serialize, Deserialize, Debug, Copy, Clone, PartialEq, Eq, Hash)]
pub enum CellRefCoord {
    Relative(i64),
    Absolute(i64),
}
impl Default for CellRefCoord {
    fn default() -> Self {
        Self::Relative(0)
    }
}
impl fmt::Display for CellRefCoord {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match *self {
            CellRefCoord::Relative(delta) => write!(f, "[{delta}]"),
            CellRefCoord::Absolute(coord) => {
                if coord < 0 {
                    write!(f, "n{}", -coord)
                } else {
                    write!(f, "{coord}")
                }
            }
        }
    }
}
impl FromStr for CellRefCoord {
    type Err = ();

    fn from_str(s: &str) -> Result<Self, Self::Err> {
        // IIFE to mimic try_block
        // !mark
        let maybe_relative = (|| s.strip_prefix('[')?.strip_suffix(']')?.parse().ok())();
        if let Some(rel) = maybe_relative {
            Ok(Self::Relative(rel))
        } else if let Ok(abs) = s.parse() {
            Ok(Self::Absolute(abs))
        } else {
            Err(())
        }
    }
}
```

## !!steps Resolving and printing a single axis

Four small methods finish the type. `resolve_from` is the one line that defines
relative-versus-absolute: add the delta, or ignore the base entirely.
`prefix` re-emits the `$` when rendering. `col_string` and `row_string` differ
only in that columns go through `column_name` in
[util.rs](/docs/quadratic-core/src/util.rs) to become letters, while rows print
as numbers — and both resolve to an absolute value first, which is why passing
a *new* base to `a1_string` rewrites relative references while leaving absolute
ones untouched.

```rust ! cell_ref.rs
impl CellRefCoord {
    /// Resolves the reference to an absolute coordinate, given the cell
    /// coordinate where evaluation is taking place.
    pub fn resolve_from(self, base: i64) -> i64 {
        match self {
            // !mark(1:2)
            CellRefCoord::Relative(delta) => base + delta,
            CellRefCoord::Absolute(coord) => coord,
        }
    }
    /// Returns the `$` prefix if this is an absolute reference, or the empty
    /// string if it is a relative reference.
    fn prefix(self) -> &'static str {
        match self {
            CellRefCoord::Relative(_) => "",
            CellRefCoord::Absolute(_) => "$",
        }
    }
    /// Returns the human-friendly string representing this coordinate, if it is
    /// a column coordinate.
    fn col_string(self, base: i64) -> String {
        let col = crate::util::column_name(self.resolve_from(base));
        format!("{}{col}", self.prefix())
    }
    /// Returns the human-friendly string representing this coordinate, if it is
    /// a row coordinate.
    fn row_string(self, base: i64) -> String {
        let row = self.resolve_from(base);
        format!("{}{row}", self.prefix())
    }
}
```

References enter the engine through the
[parser](/docs/quadratic-core/src/formulas/parser/rules/atoms.rs), which calls
`CellRef::parse_a1` on the token the
[lexer](/docs/quadratic-core/src/formulas/lexer.rs) produced, and are stored in
the [AST](/docs/quadratic-core/src/formulas/ast.rs). At evaluation time
[ctx.rs](/docs/quadratic-core/src/formulas/ctx.rs) resolves them against the
current cell and asks the
[GridProxy](/docs/quadratic-core/src/formulas/grid_proxy.rs) for contents.
[lib.rs](/docs/quadratic-core/src/lib.rs) exports them to the app both as
locations (`JsCellRefSpan`) and as rewritten formula text via `adjust_formula`
and `relocate_formula`, which
[runFormula.ts](/docs/src/lib/formulas/runFormula.ts) wraps for
[state.svelte.ts](/docs/src/lib/state.svelte.ts).
