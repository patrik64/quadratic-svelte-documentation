The middle of the pipeline. `ast.rs` defines the tree the
[parser](/docs/quadratic-core/src/formulas/parser/mod.rs) produces, and — in the
same file — the interpreter that walks it. There is no separate evaluator
module: `eval` is an inherent method on the AST node.

The tree is deliberately tiny. Six node kinds cover the whole formula language,
because operators are not a separate node type: `1 + 2` is parsed as a
`FunctionCall` whose `func` is the string `"+"`, so binary, prefix, and suffix
operators all reuse the function-dispatch path.

## !!steps A formula is one node

`Formula` is a thin wrapper around a single root `AstNode`; its `Display` just
forwards to that node, so printing a formula renders it back as source text. The
whole tree derives `Serialize` and `Deserialize`, so a parsed formula can be
carried around as data.

The key line is the type alias: `AstNode` is `Spanned<AstNodeContents>`. Every
node in the tree carries the byte range it was parsed from, which is what makes
runtime errors point at the exact sub-expression that failed.

```rust ! ast.rs
/// Abstract syntax tree of a formula expression.
#[derive(Serialize, Deserialize, Debug, Clone)]
pub struct Formula {
    pub ast: AstNode,
}
impl fmt::Display for Formula {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        fmt::Display::fmt(&self.ast, f)
    }
}

// !mark
pub type AstNode = Spanned<AstNodeContents>;

#[derive(Serialize, Deserialize, Debug, Clone)]
pub enum AstNodeContents {
    FunctionCall {
        func: Spanned<String>,
        args: Vec<AstNode>,
    },
    Paren(Box<AstNode>),
    Array(Vec<Vec<AstNode>>),
    CellRef(CellRef),
    String(String),
    Number(f64),
}
```

## !!steps Printing the tree back out

`Display` reconstructs source text from the tree. Function calls are always
printed in call syntax — `f(a, b)` — even for what the user wrote as `a + b`,
since the AST no longer distinguishes them. `Paren` is kept as a node rather
than being folded away, so explicit grouping survives a round trip.

Array literals print in the spreadsheet convention: elements joined by `, `
within a row, rows joined by `; `, wrapped in braces. Strings and numbers use
Rust's `Debug` formatting (`{s:?}` and `{n:?}`) so quoting and float precision
are handled for free.

```rust ! ast.rs
impl fmt::Display for AstNodeContents {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            AstNodeContents::FunctionCall { func, args } => {
                write!(f, "{func}(")?;
                if let Some(first) = args.first() {
                    write!(f, "{first}")?;
                    for arg in args.iter().skip(1) {
                        write!(f, ", {arg}")?;
                    }
                }
                write!(f, ")")?;
                Ok(())
            }
            AstNodeContents::Paren(contents) => write!(f, "({contents})"),
            // !mark(1:4)
            AstNodeContents::Array(a) => write!(
                f,
                "{{{}}}",
                a.iter().map(|row| row.iter().join(", ")).join("; "),
            ),
            AstNodeContents::CellRef(cellref) => write!(f, "{cellref}"),
            AstNodeContents::String(s) => write!(f, "{s:?}"),
            AstNodeContents::Number(n) => write!(f, "{n:?}"),
        }
    }
}
```

## !!steps Naming a node for error messages

`type_string` produces the phrase used in "expected X, got Y" errors. Since
operators are stored as function calls, it inspects the callee name to recover
the distinction the AST dropped: the six comparison spellings report as
"comparison", a name made only of alphanumerics and underscores reports as
"function call", and anything else — `+`, `&`, `%` — reports as "expression".

`to_cell_ref` is the one place a node is coerced back to a specific shape. It
accepts a `CellRef` node, transparently unwraps `Paren` so `(A1):(B2)` works,
and otherwise builds a `FormulaErrorMsg::Expected` error attached to
`self.span`. Note that `Paren` also delegates `type_string` to its contents, so
the error names the inner expression rather than "parentheses".

```rust ! ast.rs
impl AstNodeContents {
    fn type_string(&self) -> &'static str {
        match self {
            AstNodeContents::FunctionCall { func, .. } => match func.inner.as_str() {
                "=" | "==" | "<>" | "!=" | "<" | ">" | "<=" | ">=" => "comparison",
                s if s.chars().all(|c| c.is_alphanumeric() || c == '_') => "function call",
                _ => "expression",
            },
            AstNodeContents::Paren(contents) => contents.inner.type_string(),
            AstNodeContents::Array(_) => "array literal",
            AstNodeContents::CellRef(_) => "cell reference",
            AstNodeContents::String(_) => "string literal",
            AstNodeContents::Number(_) => "numeric literal",
        }
    }
}
impl Spanned<AstNodeContents> {
    pub fn to_cell_ref(&self) -> FormulaResult<CellRef> {
        match &self.inner {
            AstNodeContents::CellRef(cellref) => Ok(*cellref),
            // !mark
            AstNodeContents::Paren(contents) => contents.to_cell_ref(),
            _ => Err(FormulaErrorMsg::Expected {
                expected: "cell reference".into(),
                got: Some(self.inner.type_string().into()),
            }
            .with_span(self.span)),
        }
    }
}
```

## !!steps Async all the way down, and a box to make it compile

Evaluation is `async` because reading a cell goes through a `GridProxy`, which
in the browser is a JavaScript callback. `eval` builds a fresh
[`Ctx`](/docs/quadratic-core/src/formulas/ctx.rs) holding the grid proxy and the
formula's own position, then evaluates the root node.

`eval_blocking` is the synchronous escape hatch — `pollster::block_on` drives
the future to completion on the current thread, and the doc comment scopes it to
grid proxies that are not actually async. The recursive `eval` on `AstNode` has
to return a `LocalBoxFuture` rather than an `async fn`: a recursive async
function needs an indirection to have a finite size, and the comment links to
the async book chapter that explains it.

```rust ! ast.rs
impl Formula {
    /// Evaluates a formula, blocking on async calls.
    ///
    /// Use this when the grid proxy isn't actually doing anything async.
    pub fn eval_blocking(
        &self,
        grid: &mut dyn GridProxy,
        pos: Pos,
    ) -> FormulaResult<Spanned<Value>> {
        pollster::block_on(self.eval(grid, pos))
    }

    /// Evaluates a formula.
    pub async fn eval(&self, grid: &mut dyn GridProxy, pos: Pos) -> FormulaResult<Spanned<Value>> {
        // !mark
        self.ast.eval(&mut Ctx { grid, pos }).await
    }
}

impl AstNode {
    fn eval<'ctx: 'a, 'a>(
        &'a self,
        ctx: &'a mut Ctx<'ctx>,
    ) -> LocalBoxFuture<'a, FormulaResult<Spanned<Value>>> {
        // See this link for why we need to box here:
        // https://rust-lang.github.io/async-book/07_workarounds/04_recursion.html
        async move { self.eval_inner(ctx).await }.boxed_local()
    }
```

## !!steps The range operator builds an array

`eval_inner` is one big `match`, and the first arm is special-cased on the
callee name `":"`. Its two arguments are not evaluated as values — they are
coerced with `to_cell_ref` and resolved against `ctx.pos`, turning relative
references into absolute grid positions.

The corners are then normalized with `min`/`max` on each axis, so `B4:A1` and
`A1:B4` describe the same rectangle. The loop reads every cell in row-major
order into a `Value::Array`; each cell goes through `ctx.get_cell`, which
detects circular references and substitutes an empty value for blank cells.

```rust ! ast.rs
    async fn eval_inner<'ctx: 'a, 'a>(
        &'a self,
        ctx: &'a mut Ctx<'ctx>,
    ) -> FormulaResult<Spanned<Value>> {
        let value = match &self.inner {
            // Cell range
            AstNodeContents::FunctionCall { func, args } if func.inner == ":" => {
                if args.len() != 2 {
                    internal_error!("invalid arguments to cell range operator");
                }
                // !mark(1:2)
                let corner1 = args[0].to_cell_ref()?.resolve_from(ctx.pos);
                let corner2 = args[1].to_cell_ref()?.resolve_from(ctx.pos);

                let x1 = std::cmp::min(corner1.x, corner2.x);
                let y1 = std::cmp::min(corner1.y, corner2.y);

                let x2 = std::cmp::max(corner1.x, corner2.x);
                let y2 = std::cmp::max(corner1.y, corner2.y);

                let mut array = vec![];
                for y in y1..=y2 {
                    let mut row = smallvec![];
                    for x in x1..=x2 {
                        let cell_ref = CellRef::absolute(Pos { x, y });
                        row.push(ctx.get_cell(cell_ref, self.span).await?);
                    }
                    array.push(row);
                }

                Value::Array(array)
            }
```

## !!steps Two functions that must see their arguments fail

`IFERROR` and `ISERROR` cannot be ordinary functions. The generic path below
evaluates every argument first and propagates the first error with `?`, which
would mean an erroring argument never reaches the function at all. The comment
names this directly: these forms "observe errors in their arguments instead of
propagating them".

So both are handled inline and lazily. `IFERROR` evaluates its first argument
and, on `Err`, evaluates the fallback instead — the second argument is untouched
in the success case. `ISERROR` evaluates its single argument purely for whether
it succeeded, discarding the value. Both match the callee name with
`eq_ignore_ascii_case`, so formula names are case-insensitive.

```rust ! ast.rs
            // Lazy special forms: these observe errors in their arguments
            // instead of propagating them, so they cannot go through the
            // eager-evaluation path below.
            AstNodeContents::FunctionCall { func, args } if func.inner.eq_ignore_ascii_case("IFERROR") => {
                if args.len() != 2 {
                    return Err(FormulaErrorMsg::BadArgumentCount.with_span(self.span));
                }
                // !mark(1:4)
                match args[0].eval(&mut *ctx).await {
                    Ok(v) => v.inner,
                    Err(_) => args[1].eval(&mut *ctx).await?.inner,
                }
            }
            AstNodeContents::FunctionCall { func, args } if func.inner.eq_ignore_ascii_case("ISERROR") => {
                if args.len() != 1 {
                    return Err(FormulaErrorMsg::BadArgumentCount.with_span(self.span));
                }
                Value::Bool(args[0].eval(&mut *ctx).await.is_err())
            }
```

## !!steps Everything else is a function lookup

The general arm is eager: arguments are evaluated left to right in a plain loop
(sequentially, not concurrently — each `await` completes before the next starts),
and the collected values are wrapped in a single `Spanned` carrying the *call
site's* span. That is what lets a function report an arity error pointing at the
whole call.

`functions::lookup_function` resolves the name against the function table; the
found entry's `eval` is invoked with the context and arguments. The failure
branch is a nice touch: if the name is not implemented here but *is* a valid
Excel function, the user gets `UnimplementedExcelFunction` with the uppercased
name instead of a generic "bad function name", and the error is spanned to
`func.span` — just the identifier, not the arguments.

```rust ! ast.rs
            // Other operator/function
            AstNodeContents::FunctionCall { func, args } => {
                let mut arg_values = vec![];
                for arg in args {
                    arg_values.push(arg.eval(&mut *ctx).await?);
                }
                let spanned_arg_values = Spanned {
                    span: self.span,
                    inner: arg_values,
                };

                let func_name = &func.inner;
                match functions::lookup_function(&func_name) {
                    // !mark
                    Some(f) => (f.eval)(&mut *ctx, spanned_arg_values).await?,
                    None => {
                        let msg = if functions::excel::is_valid_excel_function(func_name) {
                            FormulaErrorMsg::UnimplementedExcelFunction(func_name.to_uppercase())
                        } else {
                            FormulaErrorMsg::BadFunctionName
                        };
                        return Err(msg.with_span(func.span));
                    }
                }
            }
```

## !!steps The leaves

The remaining arms are short. `Paren` evaluates its contents and unwraps the
inner value, discarding the child's span — the result is re-spanned at the end
with the paren node's own span. Array literals evaluate every element in reading
order into a `Value::Array`, using `smallvec` for rows just like the range
operator does.

A bare `CellRef` is a single `ctx.get_cell`, and the two literal kinds simply
clone or copy their payload into a `Value`. Whatever branch ran, the tail wraps
the result in `Spanned` with `self.span`, so the value that flows back up the
tree stays attached to the source text that produced it.

```rust ! ast.rs
            AstNodeContents::Paren(expr) => expr.eval(ctx).await?.inner,

            AstNodeContents::Array(a) => {
                let mut array_of_values = vec![];
                for row in a {
                    let mut row_of_values = smallvec![];
                    for elem_expr in row {
                        row_of_values.push(elem_expr.eval(ctx).await?.inner);
                    }
                    array_of_values.push(row_of_values);
                }
                Value::Array(array_of_values)
            }

            AstNodeContents::CellRef(cell_ref) => ctx.get_cell(*cell_ref, self.span).await?,

            AstNodeContents::String(s) => Value::String(s.clone()),

            AstNodeContents::Number(n) => Value::Number(*n),
        };

        // !mark(1:4)
        Ok(Spanned {
            span: self.span,
            inner: value,
        })
    }
}
```

The tree comes from
[parser/rules/expression.rs](/docs/quadratic-core/src/formulas/parser/rules/expression.rs),
which is where operators get lowered into `FunctionCall` nodes with the operator
text as the callee. The function table `eval` calls into lives in
[functions/mod.rs](/docs/quadratic-core/src/formulas/functions/mod.rs) — with
operators themselves implemented in
[functions/operators.rs](/docs/quadratic-core/src/formulas/functions/operators.rs).
The values produced here are defined in
[value.rs](/docs/quadratic-core/src/formulas/value.rs), cell reading and circular
reference detection in [ctx.rs](/docs/quadratic-core/src/formulas/ctx.rs), the
reference type in [cell_ref.rs](/docs/quadratic-core/src/formulas/cell_ref.rs),
and the error types in
[errors.rs](/docs/quadratic-core/src/formulas/errors.rs).
