Every built-in spreadsheet function — `SUM`, `IF`, even the `+` operator — is
a `FormulaFunction` value living in one global `HashMap`. This module defines
that type, collects the per-category modules into the map, and exposes
`lookup_function`, the single entry point the evaluator in
[ast.rs](/docs/quadratic-core/src/formulas/ast.rs) calls to resolve a name.

<Scrollycoding>

## !!steps One submodule per category

The function library is split into thirteen submodules, one per category
(plus `util`, the shared toolbox). `util` is declared with `#[macro_use]`
and comes first; everything else is private except `excel`, which is
re-exported for callers outside the formula engine.

```rust ! mod.rs
use futures::{future::LocalBoxFuture, FutureExt};
use itertools::Itertools;
use lazy_static::lazy_static;
use std::collections::HashMap;

// !mark(1:2)
#[macro_use]
mod util;
mod array;
mod database;
mod datetime;
mod engineering;
pub mod excel;
mod financial;
mod logic;
mod lookup;
mod mathematics;
mod operators;
mod statistics;
mod string;
mod trigonometry;

use super::{Ctx, FormulaErrorMsg, FormulaResult, Span, Spanned, Value};
```

## !!steps The registry

Each category module exports a `CATEGORY` constant; the `CATEGORIES` slice
fixes their order for documentation. `ALL_FUNCTIONS` is built lazily on first
access by calling every category's `get_functions` and keying the results by
name. Lookup uppercases the query first, so `sum(...)` and `SUM(...)` hit the
same entry.

```rust ! mod.rs
pub fn lookup_function(name: &str) -> Option<&'static FormulaFunction> {
    // !mark
    ALL_FUNCTIONS.get(name.to_ascii_uppercase().as_str())
}

pub const CATEGORIES: &[FormulaFunctionCategory] = &[
    operators::CATEGORY,
    mathematics::CATEGORY,
    trigonometry::CATEGORY,
    statistics::CATEGORY,
    logic::CATEGORY,
    string::CATEGORY,
    lookup::CATEGORY,
    datetime::CATEGORY,
    array::CATEGORY,
    database::CATEGORY,
    engineering::CATEGORY,
    financial::CATEGORY,
];

lazy_static! {
    pub static ref ALL_FUNCTIONS: HashMap<&'static str, FormulaFunction> = {
        CATEGORIES
            .iter()
            .flat_map(|category| (category.get_functions)())
            .map(|function| (function.name, function))
            .collect()
    };
}
```

## !!steps What a function is

`FormulaFn` is the universal calling convention: a boxed closure that takes
the evaluation context ([ctx.rs](/docs/quadratic-core/src/formulas/ctx.rs))
plus a spanned list of already-evaluated, spanned argument values, and returns
a future — futures because reading cells can be asynchronous. Around it,
`FormulaFunction` bundles the metadata the editor needs: usage strings,
examples, doc text, and an autocomplete snippet.

The two `NonVariadic` aliases describe simpler shapes — a plain function over
a fixed-size argument array — that get adapted into `FormulaFn` by the
constructors below.

```rust ! mod.rs
pub type FormulaFn = Box<
    dyn 'static
        + Send
        + Sync
        + for<'a> Fn(
            &'a mut Ctx<'_>,
            Spanned<Vec<Spanned<Value>>>,
        ) -> LocalBoxFuture<'a, FormulaResult>,
>;

type NonVariadicPureFn<const N: usize> = fn([Spanned<Value>; N]) -> FormulaResult;
type NonVariadicFn<const N: usize> = fn(&mut Ctx<'_>, [Spanned<Value>; N]) -> FormulaResult;

pub struct FormulaFunction {
    pub name: &'static str,
    pub arg_completion: &'static str,
    pub usages: &'static [&'static str],
    pub examples: &'static [&'static str],
    pub doc: &'static str,
    pub eval: FormulaFn,
}
```

## !!steps Operators with one or two arities

`-` means negation with one argument and subtraction with two.
`variadic_operator` encodes that: two const generics `N1` and `N2` name the
monadic and dyadic arities, each with an optional implementation. At call time
the argument count picks the branch; a missing branch is a
`BadArgumentCount` error. Both branches go through `ctx.array_map`, which
distributes the scalar operation over array arguments elementwise.

```rust ! mod.rs
    fn variadic_operator<const N1: usize, const N2: usize>(
        name: &'static str,
        eval_monadic: Option<NonVariadicFn<N1>>,
        eval_dyadic: Option<NonVariadicFn<N2>>,
    ) -> Self {
        FormulaFunction {
            name,
            arg_completion: "",
            usages: &[],
            examples: &[],
            doc: "",
            eval: Box::new(move |ctx, args| {
                async move {
                    // !mark
                    if args.inner.len() == N1 {
                        let Some(eval_fn) = eval_monadic else {
                            return Err(FormulaErrorMsg::BadArgumentCount.with_span(args.span));
                        };
                        ctx.array_map(args, eval_fn).await
                    } else {
                        let Some(eval_fn) = eval_dyadic else {
                            return Err(FormulaErrorMsg::BadArgumentCount.with_span(args.span));
                        };
                        ctx.array_map(args, eval_fn).await
                    }
                }
                .boxed_local()
            }),
        }
    }
```

## !!steps Fixed-arity operators and editor strings

The simpler `operator` constructor wraps a pure fixed-arity function via
`util::array_mapped` and leaves all documentation fields empty — operators are
hidden from docs anyway. The two string helpers below feed the formula
editor's language server: `usages_strings` renders each usage as
`NAME(args)`, and `autocomplete_snippet` builds the insert-on-tab text from
`arg_completion`.

```rust ! mod.rs
    fn operator<const N: usize>(name: &'static str, eval_fn: NonVariadicPureFn<N>) -> Self {
        Self {
            name,
            arg_completion: "",
            usages: &[],
            examples: &[],
            doc: "",
            // !mark
            eval: util::array_mapped(eval_fn),
        }
    }
    // ...
    pub fn usages_strings(&self) -> impl Iterator<Item = String> {
        let name = self.name;
        self.usages
            .iter()
            .map(move |args| format!("{name}({args})"))
    }

    pub fn autocomplete_snippet(&self) -> String {
        let name = self.name;
        let arg_completion = self.arg_completion;
        format!("{name}({arg_completion})")
    }
```

## !!steps Markdown docs and the category type

`lsp_full_docs` assembles the hover documentation shown in the editor:
a Description section from `doc` and an Examples section rendering each
example as a code-span bullet. Finally, `FormulaFunctionCategory` is the
contract every submodule fulfills — two visibility flags (operators set both
to false), a display name, category-level docs, and the `get_functions`
producer the registry calls.

```rust ! mod.rs
    pub fn lsp_full_docs(&self) -> String {
        let mut ret = String::new();
        if !self.doc.is_empty() {
            ret.push_str(&format!("# Description\n\n{}\n\n", self.doc));
        }
        if !self.examples.is_empty() {
            let examples = self.examples.iter().map(|s| format!("- `{s}`\n")).join("");
            ret.push_str(&format!("# Examples\n\n{examples}\n\n"));
        }
        ret
    }
}

pub struct FormulaFunctionCategory {
    pub include_in_docs: bool,
    pub include_in_completions: bool,
    pub name: &'static str,
    pub docs: &'static str,
    // !mark
    pub get_functions: fn() -> Vec<FormulaFunction>,
}
```
