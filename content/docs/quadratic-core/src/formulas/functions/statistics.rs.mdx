This module is the "Statistics functions" category of the formula engine. It is
deliberately small: nine functions that reduce a pile of arguments — scalars,
ranges, arrays, or any mix — down to a single number. What makes it interesting
is not the arithmetic but the *bookkeeping*: which values count, which are
silently skipped, and which quietly convert to zero.

It also owns `Criterion`, the Excel-style criteria parser behind `COUNTIF`,
`SUMIF`, and `AVERAGEIF`. That type is `pub(super)`, so
[database.rs](/docs/quadratic-core/src/formulas/functions/database.rs) imports
it to evaluate its criteria tables against the same rules. Like every sibling
module, registration happens through a single `CATEGORY` constant that
[functions/mod.rs](/docs/quadratic-core/src/formulas/functions/mod.rs) folds
into the global `ALL_FUNCTIONS` map.

## !!steps The category, and why AVERAGE is not sum over length

`CATEGORY` is the registration point: a name, category docs, and a
`get_functions` pointer that builds the `FormulaFunction` values on demand.

`AVERAGE` looks trivial, but the numerator and denominator come from two
*different* helpers, and that asymmetry is the whole behavior. `util::sum`
walks every value that converts to a number, and a blank cell converts to `0`;
`util::count_numeric` explicitly returns 0 for an empty string. So blanks add
nothing to the total and nothing to the divisor, while genuinely non-numeric
text is skipped by both. `AVERAGE("", "a", 12, -3.5, 42.5)` is therefore
`51 / 3`, not `51 / 5`.

```rust ! statistics.rs
pub const CATEGORY: FormulaFunctionCategory = FormulaFunctionCategory {
    include_in_docs: true,
    include_in_completions: true,
    name: "Statistics functions",
    docs: "",
    get_functions,
};

fn get_functions() -> Vec<FormulaFunction> {
    vec![
        FormulaFunction {
            name: "AVERAGE",
            arg_completion: "${1:a, b, ...}",
            usages: &["a, b, ..."],
            examples: &["AVERAGE(A1:A6)", "AVERAGE(A1, A3, A5, B1:B6)"],
            doc: "Returns the arithmetic mean of all values.",
            eval: util::pure_fn(|args| {
                Ok(Value::Number(
                    // !mark
                    util::sum(&args.inner) / util::count_numeric(&args.inner) as f64,
                ))
            }),
        },
```

## !!steps COUNT, MIN and MAX over a flattened stream

`COUNT` exposes `count_numeric` directly, so it agrees with `AVERAGE`'s
divisor by construction.

`MIN` and `MAX` fold `util::flat_iter_numbers` — every argument flattened and
converted, non-numeric values dropped — starting from `+∞` and `-∞`
respectively. Two consequences fall straight out of the seed values: with no
numeric input at all the identity element is returned rather than an error
(documented in each `doc` string), and because a blank cell *does* convert to
`0`, blanks inside a range participate as zeros rather than being ignored.

```rust ! statistics.rs
        FormulaFunction {
            name: "COUNT",
            arg_completion: "${1:a, b, ...}",
            usages: &["a, b, ..."],
            examples: &["COUNT(A1:C42, E17)", "SUM(A1:A10) / COUNT(A1:A10)"],
            doc: "Returns the number of numeric values.",
            eval: util::pure_fn(|args| Ok(Value::Number(util::count_numeric(&args.inner) as f64))),
        },
        FormulaFunction {
            name: "MIN",
            arg_completion: "${1:a, b, ...}",
            usages: &["a, b, ..."],
            examples: &["MIN(A1:A6)", "MIN(0, A1:A6)"],
            doc: "Returns the smallest value.\nReturns +∞ if given no values.",
            eval: util::pure_fn(|args| {
                Ok(Value::Number(
                    // !mark
                    util::flat_iter_numbers(&args.inner).fold(f64::INFINITY, f64::min),
                ))
            }),
        },
        FormulaFunction {
            name: "MAX",
            arg_completion: "${1:a, b, ...}",
            usages: &["a, b, ..."],
            examples: &["MAX(A1:A6)", "MAX(0, A1:A6)"],
            doc: "Returns the largest value.\nReturns -∞ if given no values.",
            eval: util::pure_fn(|args| {
                Ok(Value::Number(
                    // !mark
                    util::flat_iter_numbers(&args.inner).fold(-f64::INFINITY, f64::max),
                ))
            }),
        },
```

## !!steps Counting cells instead of numbers

`COUNTA` and `COUNTBLANK` are the only two functions here that care about
values rather than numbers, and they are exact mirrors: one filter is the
negation of the other, so together they always account for every cell.

"Blank" has a precise meaning in this engine — a `Value::String` that
`is_empty()`. The test is on the raw string, not a trimmed one, so a cell
containing a single space is *not* blank and is counted by `COUNTA`. Note also
that numbers, booleans, and text all count as non-empty; the pattern match only
singles out the empty string.

```rust ! statistics.rs
        FormulaFunction {
            name: "COUNTA",
            arg_completion: "${1:a, b, ...}",
            usages: &["a, b, ..."],
            examples: &["COUNTA(A1:A10)"],
            doc: "Returns the number of non-empty values.",
            eval: util::pure_fn(|args| {
                let count: usize = args
                    .inner
                    .iter()
                    .flat_map(|v| flatten_values(&v.inner))
                    // !mark
                    .filter(|v| !matches!(v, Value::String(s) if s.is_empty()))
                    .count();
                Ok(Value::Number(count as f64))
            }),
        },
        FormulaFunction {
            name: "COUNTBLANK",
            arg_completion: "${1:a, b, ...}",
            usages: &["a, b, ..."],
            examples: &["COUNTBLANK(A1:A10)"],
            doc: "Returns the number of empty values.",
            eval: util::pure_fn(|args| {
                let count: usize = args
                    .inner
                    .iter()
                    .flat_map(|v| flatten_values(&v.inner))
                    // !mark
                    .filter(|v| matches!(v, Value::String(s) if s.is_empty()))
                    .count();
                Ok(Value::Number(count as f64))
            }),
        },
```

## !!steps COUNTIF and the local flattener

`COUNTIF` sets the shape for the whole conditional family: pull exactly two
arguments out with `two_args` (which stringifies the criteria and errors with
`BadArgumentCount` if a third is present), parse the criteria once, then filter.

The flattening helper is local to this module and different from the `util`
ones: `flatten_values` produces `Vec<Value>` — the values themselves, in row
order — rather than coercing to numbers. Criteria have to inspect text and
blanks, so the raw values must survive the flattening step.

```rust ! statistics.rs
        FormulaFunction {
            name: "COUNTIF",
            arg_completion: "${1:range}, ${2:criteria}",
            usages: &["range, criteria"],
            examples: &["COUNTIF(A1:A10, \">5\")", "COUNTIF(B1:B10, \"apple*\")"],
            doc: "Returns the number of values in `range` matching `criteria`. \
                  Criteria may be a value, a comparison like `\">=10\"` or `\"<>x\"`, \
                  or text with the wildcards `*` and `?`.",
            eval: util::pure_fn(|args| {
                let (range, criteria) = two_args(args)?;
                // !mark
                let criterion = Criterion::parse(&criteria);
                let count = flatten_values(&range.inner)
                    .iter()
                    .filter(|v| criterion.matches(v))
                    .count();
                Ok(Value::Number(count as f64))
            }),
        },
// ...
/// Flattens a value (possibly an array) into a list of scalar values.
fn flatten_values(v: &Value) -> Vec<Value> {
    match v {
        Value::Array(rows) => rows.iter().flatten().cloned().collect(),
        other => vec![other.clone()],
    }
}
```

## !!steps Testing one range, summing another

`SUMIF` and `AVERAGEIF` take an optional third range: the criteria are checked
against `range`, but the arithmetic uses the *corresponding* entries of
`sum_range` / `average_range`. "Corresponding" is implemented by `zip` over the
two flattened lists, which means the pairing is strictly positional and stops
at the shorter of the two — a mismatched second range is truncated, not an
error. When the third argument is omitted, the test list is cloned and each
value is compared against itself.

The two differ only at the end. `SUMIF` sums the surviving values, so no
matches yields `0`. `AVERAGEIF` has to divide, so it checks for an empty
result set first and raises `DivideByZero` at the call's span rather than
returning `NaN`.

```rust ! statistics.rs
            eval: util::pure_fn(|args| {
                let (range, criteria, other) = two_or_three_args(args)?;
                let criterion = Criterion::parse(&criteria);
                let test_values = flatten_values(&range.inner);
                let sum_values = match &other {
                    Some(v) => flatten_values(&v.inner),
                    None => test_values.clone(),
                };
                let total: f64 = test_values
                    .iter()
                    // !mark
                    .zip(sum_values.iter())
                    .filter(|(test, _)| criterion.matches(test))
                    .filter_map(|(_, v)| v.to_number().ok())
                    .sum();
                Ok(Value::Number(total))
            }),
// ...
                let numbers: Vec<f64> = test_values
                    .iter()
                    .zip(avg_values.iter())
                    .filter(|(test, _)| criterion.matches(test))
                    .filter_map(|(_, v)| v.to_number().ok())
                    .collect();
                if numbers.is_empty() {
                    // !mark
                    return Err(FormulaErrorMsg::DivideByZero.with_span(span));
                }
                Ok(Value::Number(numbers.iter().sum::<f64>() / numbers.len() as f64))
            }),
```

## !!steps Parsing a criteria string

`Criterion::parse` strips an optional comparison prefix, and the order of the
`strip_prefix` chain is what makes it correct: the two-character operators
`>=`, `<=`, and `<>` are tried before the single-character `>`, `<`, and `=`,
so `">=10"` is not read as `>` followed by the text `"=10"`.

Whatever remains decides the variant. If the rest parses as an `f64` the
criterion becomes a numeric comparison; otherwise it becomes a text comparison,
lowercased so that matching is case-insensitive. With no prefix at all, a
numeric string yields `MatchNumber` and anything else yields `MatchText`, which
is the only variant that goes through wildcard matching.

```rust ! statistics.rs
impl Criterion {
    pub(super) fn parse(criteria: &str) -> Self {
        // !mark(1:3)
        let (op, rest) = if let Some(rest) = criteria.strip_prefix(">=") {
            (Some(CompareOp::Ge), rest)
        } else if let Some(rest) = criteria.strip_prefix("<=") {
            (Some(CompareOp::Le), rest)
        } else if let Some(rest) = criteria.strip_prefix("<>") {
            (Some(CompareOp::Ne), rest)
        } else if let Some(rest) = criteria.strip_prefix('>') {
            (Some(CompareOp::Gt), rest)
        } else if let Some(rest) = criteria.strip_prefix('<') {
            (Some(CompareOp::Lt), rest)
        } else if let Some(rest) = criteria.strip_prefix('=') {
            (Some(CompareOp::Eq), rest)
        } else {
            (None, criteria)
        };
        match op {
            Some(op) => match rest.trim().parse::<f64>() {
                Ok(n) => Criterion::CompareNumber(op, n),
                Err(_) => Criterion::CompareText(op, rest.to_lowercase()),
            },
            None => match criteria.trim().parse::<f64>() {
                Ok(n) => Criterion::MatchNumber(n),
                Err(_) => Criterion::MatchText(criteria.to_lowercase()),
            },
        }
    }
```

## !!steps Matching, and the blank-cell guard

`matches` contains the subtlest rule in the file. `Value::to_number` returns
`Ok(0.0)` for an empty or whitespace-only string, so without intervention every
blank cell in a range would satisfy `"<1"` or `"=0"`. Both numeric variants
therefore re-inspect the original value and reject blanks explicitly *before*
comparing — the same guard appears in `CompareNumber` and in `MatchNumber`.

Text comparisons lowercase both sides and then use Rust's ordinary string
ordering for `<` and `>`, so ranking is lexicographic. `MatchText` is the
wildcard path: it hands the lowercased pattern and value to
`util::wildcard_match`, which supports `*`, `?`, and `~` as an escape.

```rust ! statistics.rs
    pub(super) fn matches(&self, value: &Value) -> bool {
        match self {
            Criterion::CompareNumber(op, n) => match value.to_number() {
                Ok(v) => {
                    // empty cells never match numeric comparisons
                    // !mark
                    if matches!(value, Value::String(s) if s.trim().is_empty()) {
                        return false;
                    }
                    compare(*op, v, *n)
                }
                Err(_) => false,
            },
            Criterion::CompareText(op, text) => {
                let v = value.to_string().to_lowercase();
                match op {
                    CompareOp::Eq => v == *text,
                    CompareOp::Ne => v != *text,
                    CompareOp::Lt => v < *text,
                    CompareOp::Le => v <= *text,
                    CompareOp::Gt => v > *text,
                    CompareOp::Ge => v >= *text,
                }
            }
            Criterion::MatchNumber(n) => value.to_number().is_ok_and(|v| {
                !matches!(value, Value::String(s) if s.trim().is_empty()) && v == *n
            }),
            Criterion::MatchText(pattern) => {
                // !mark
                util::wildcard_match(pattern, &value.to_string().to_lowercase())
            }
        }
    }
```

## Implemented functions

| Name | Purpose |
| --- | --- |
| AVERAGE | Arithmetic mean of all numeric values, blanks excluded from the divisor |
| COUNT | Number of numeric values |
| MIN | Smallest value; positive infinity when given no values |
| MAX | Largest value; negative infinity when given no values |
| COUNTA | Number of non-empty values |
| COUNTBLANK | Number of empty values |
| COUNTIF | Number of values in a range matching a criteria string |
| SUMIF | Sum of matching values, optionally taken from a parallel sum range |
| AVERAGEIF | Mean of matching values, optionally taken from a parallel average range |

The helpers every `eval` here leans on — `pure_fn`, `sum`, `count_numeric`,
`flat_iter_numbers`, and `wildcard_match` — live in
[functions/util.rs](/docs/quadratic-core/src/formulas/functions/util.rs), and
the conversion rules that decide what counts as a number are in
[value.rs](/docs/quadratic-core/src/formulas/value.rs).
[database.rs](/docs/quadratic-core/src/formulas/functions/database.rs) reuses
`Criterion` for its criteria tables, and
[mathematics.rs](/docs/quadratic-core/src/formulas/functions/mathematics.rs)
provides the plain `SUM` and `PRODUCT` aggregates that these build on. The
registry that consumes `CATEGORY` is
[functions/mod.rs](/docs/quadratic-core/src/formulas/functions/mod.rs).
