Twenty-seven functions in about 120 lines of declarations: six circular
functions, six hyperbolic ones, an inverse for each, the two angle-unit
converters, and `ATAN2`. Almost none of them are written out by hand — a
`macro_rules!` macro defined *inside* `get_functions` expands one table row
into a matched pair of `FormulaFunction` values.

Like every sibling in this directory, the module exports a `CATEGORY`
constant whose `get_functions` pointer produces those values;
[functions/mod.rs](/docs/quadratic-core/src/formulas/functions/mod.rs) merges
all categories into the global `ALL_FUNCTIONS` map that the evaluator consults
by uppercase name.

## !!steps Angles are radians, except at the boundary

`CATEGORY` is the registration point, and `get_functions` starts by seeding a
mutable vector with the only two functions that deal in degrees at all.
`DEGREES` and `RADIANS` are thin wrappers over Rust's `f64::to_degrees` and
`f64::to_radians`; every other function in the module takes or returns
radians, which is what the shared `arg_completion` of `"${1:radians}"` in the
macro below advertises.

Both are built with `util::array_mapped`, the constructor from
[functions/util.rs](/docs/quadratic-core/src/formulas/functions/util.rs) that
distributes a scalar operation elementwise over array arguments — so
`DEGREES(A1:A10)` works without any extra code.

```rust ! trigonometry.rs
use super::*;

pub const CATEGORY: FormulaFunctionCategory = FormulaFunctionCategory {
    include_in_docs: true,
    include_in_completions: true,
    name: "Trigonometric functions",
    docs: "",
    get_functions,
};

fn get_functions() -> Vec<FormulaFunction> {
    // ...
    let mut all_trig_functions = vec![
        FormulaFunction {
            name: "DEGREES",
            arg_completion: "${1:radians}",
            usages: &["radians"],
            examples: &["DEGREES(PI() / 2)"],
            doc: "Converts radians to degrees",
            // !mark
            eval: util::array_mapped(|[radians]| {
                Ok(Value::Number(radians.to_number()?.to_degrees()))
            }),
        },
        FormulaFunction {
            name: "RADIANS",
            arg_completion: "${1:degrees}",
            usages: &["degrees"],
            examples: &["RADIANS(90)"],
            doc: "Converts degrees to radians",
            eval: util::array_mapped(|[degrees]| {
                Ok(Value::Number(degrees.to_number()?.to_radians()))
            }),
        },
    ];
```

## !!steps A macro that takes a table

`trig_functions_and_inverses!` accepts two documentation URLs followed by a
semicolon-separated table of rows. Each row carries a short name, a
human-readable full name, a closure for the function, a closure for its
inverse, and an optional range string — the `$(, $inv_range:literal)?`
fragment makes that last column skippable per row.

The first half of the expansion builds the forward function. The closure is
bound to a named `fn(f64) -> f64` first so it can be moved into the `eval`
closure, and the whole documentation string is assembled at compile time with
`concat!` — a markdown link built from the full name and the shared URL,
followed by a fixed sentence ending.

```rust ! trigonometry.rs
    macro_rules! trig_functions_and_inverses {
        (
            url: $url:literal;
            inverse_url: $inv_url:literal;
            $(
                // !mark
                $short_name:literal, $full_name:literal, $f:expr, $inv_f:expr $(, $inv_range:literal)?
            );+ $(;)?
        ) => {
            vec![
                $(
                    {
                        let f: fn(f64) -> f64 = $f;
                        FormulaFunction {
                            name: $short_name,
                            arg_completion: "${1:radians}",
                            usages: &["radians"],
                            examples: &[concat!($short_name, "(PI() * 2/3)")],
                            doc: concat!(
                                "Returns the [", $full_name, "](", $url, ") ",
                                "of an angle in radians.",
                            ),
                            eval: util::array_mapped(move |[radians]| Ok(Value::Number(f(radians.to_number()?)))),
                        }
                    },
```

## !!steps The inverse half, named by concatenation

The second half of each expansion is the inverse. Its name is
`concat!("A", $short_name)`, which is the entire naming convention: `SIN`
becomes `ASIN`, `COTH` becomes `ACOTH`. The optional range column is spliced
in with `$(", ranging from ", $inv_range,)?`, so rows that supplied one get a
sentence like "in radians, ranging from 0 to π" and rows that did not simply
end after "in radians".

Two details are worth knowing. The range text is documentation only — nothing
in the `eval` closure enforces or checks it, and the `SIN` row below declares
`0 to π` for `ASIN` even though `f64::asin` returns values from `-π/2` to
`π/2`, which is what the test table at the bottom of the file expects. And the
inverse's `examples` entry is built from `$short_name` rather than the
prefixed name, so `ASIN` lists `SIN(A1)` as its example.

```rust ! trigonometry.rs
                    {
                        let inv_f: fn(f64) -> f64 = $inv_f;
                        FormulaFunction {
                            // !mark
                            name: concat!("A", $short_name),
                            arg_completion: "${1:number}",
                            usages: &["number"],
                            examples: &[concat!($short_name, "(A1)")],
                            doc: concat!(
                                "Returns the [inverse ", $full_name, "](", $inv_url, ") ",
                                "of a number, in radians", $(", ranging from ", $inv_range,)?
                                ".",
                            ),
                            eval: util::array_mapped(move |[number]| Ok(Value::Number(inv_f(number.to_number()?)))),
                        }
                    },
                )+
            ]
        };
    }
```

## !!steps Six circular functions from six lines

The first invocation is the whole circular family, and it reads like a table
because it is one. `SIN`, `COS`, and `TAN` map onto the `f64` methods
directly. The three reciprocal functions have no `f64` equivalent, so they are
spelled as identities: cosecant is `sin(x).recip()`, secant is
`cos(x).recip()`, cotangent is `tan(x).recip()`.

Their inverses invert in the other order — `x.recip().asin()` for `ACSC`,
`x.recip().acos()` for `ASEC` — because the reciprocal has to be undone before
the arc function. `ACOT` is the exception: instead of a closure it names the
`arc_cotangent` helper, for reasons the last step explains.

```rust ! trigonometry.rs
    all_trig_functions.extend(trig_functions_and_inverses![
        url: "https://en.wikipedia.org/wiki/Trigonometric_functions";
        inverse_url: "https://en.wikipedia.org/wiki/Inverse_trigonometric_functions";
        //                              function,             inverse function,        inv_range;
        "SIN",  "sine",                 |x| x.sin(),          |x| x.asin(),            "0 to π";
        "COS",  "cosine",               |x| x.cos(),          |x| x.acos(),            "0 to π";
        "TAN",  "tangent",              |x| x.tan(),          |x| x.atan(),         "-π/2 to π/2";
        // !mark(1:3)
        "CSC",  "cosecant",             |x| x.sin().recip(),  |x| x.recip().asin(), "-π/2 to π/2";
        "SEC",  "secant",               |x| x.cos().recip(),  |x| x.recip().acos(),    "0 to π";
        "COT",  "cotangent",            |x| x.tan().recip(),  arc_cotangent,           "0 to π";
    ]);
```

## !!steps The hyperbolic family, same shape

The second invocation reuses the macro unchanged, passing the hyperbolic
Wikipedia URLs so the generated docs link to the right articles. The pattern
is identical: three direct `f64` methods, three reciprocals, and inverses that
apply `recip()` before the arc function.

The difference is what is missing — no row supplies an `inv_range`, so the
optional fragment expands to nothing and every hyperbolic inverse gets a doc
string that stops at "of a number, in radians." Twelve more functions,
eleven lines of source.

```rust ! trigonometry.rs
    all_trig_functions.extend(trig_functions_and_inverses![
        url: "https://en.wikipedia.org/wiki/Hyperbolic_functions";
        inverse_url: "https://en.wikipedia.org/wiki/Inverse_hyperbolic_functions";
        // !mark
        //                              function,             inverse function;
        "SINH", "hyperbolic sine",      |x| x.sinh(),         |x| x.asinh();
        "COSH", "hyperbolic cosine",    |x| x.cosh(),         |x| x.acosh();
        "TANH", "hyperbolic tangent",   |x| x.tanh(),         |x| x.atanh();
        "CSCH", "hyperbolic cosecant",  |x| x.sinh().recip(), |x| x.recip().asinh();
        "SECH", "hyperbolic secant",    |x| x.cosh().recip(), |x| x.recip().acosh();
        "COTH", "hyperbolic cotangent", |x| x.tanh().recip(), |x| x.recip().atanh();
    ]);
```

## !!steps ATAN2 is spliced in by index

`ATAN2` takes two arguments, so it cannot come out of the pair macro. It is
written by hand and `insert`ed at a fixed position rather than pushed, which
only affects the order functions appear in the generated documentation and
completions — the registry in
[functions/mod.rs](/docs/quadratic-core/src/formulas/functions/mod.rs) keys
everything by name. Counting the vector so far — `DEGREES`, `RADIANS`, then
the `SIN`/`ASIN`, `COS`/`ACOS`, `TAN`/`ATAN` pairs — index 6 places it
immediately before the tangent pair.

The behavior worth remembering is in the last line: the arguments are declared
`x, y`, and the doc says so explicitly, but `f64::atan2` is called as
`atan2(y, x)`. The formula-level argument order is the reverse of the usual
`atan2` convention.

```rust ! trigonometry.rs
    let index_of_atan = 5;
    all_trig_functions.insert(
        index_of_atan + 1,
        FormulaFunction {
            name: "ATAN2",
            arg_completion: "{$1:x}, {$2:y}",
            usages: &["x, y"],
            examples: &["ATAN2(2, 1)"],
            doc: "Returns the counterclockwise angle, in radians, from the X axis to the \
                  point `(x, y)`. Note that the argument order is reversed compared to \
                  the [typical `atan2()` function](https://en.wikipedia.org/wiki/Atan2).",
            eval: util::array_mapped(|[x, y]| {
                // !mark
                Ok(Value::Number(f64::atan2(y.to_number()?, x.to_number()?)))
            }),
        },
    );
```

## !!steps Why ACOT needs its own function

Every other inverse is a one-liner, and `ACOT` could have been
`|x| x.recip().atan()` — but the comment spells out why that is wrong. Taking
the reciprocal first sends `x` near zero to a huge magnitude, so the naive
version jumps from near `π/2` to near `-π/2` as `x` crosses zero, and at
exactly zero it divides by zero.

`arc_cotangent` restores a continuous branch on `0` to `π`: positive inputs
use the plain arctangent of the reciprocal, negative inputs get `π` added to
lift them into the upper half, and zero returns `FRAC_PI_2` outright. The
tests at the bottom of the file pin this down, checking `ACOT(-1)` at `0.75π`
rather than `-0.25π`.

```rust ! trigonometry.rs
/// Inverse cotangent function with the correct range.
///
/// If we just use `.recip().atan()`, then the range is discontinuous and we
/// lose `acot(0) = 0`. So this function does it properly.
fn arc_cotangent(x: f64) -> f64 {
    if x > 0.0 {
        x.recip().atan()
    } else if x < 0.0 {
        // !mark
        x.recip().atan() + std::f64::consts::PI
    } else {
        std::f64::consts::FRAC_PI_2
    }
}
```

The registry that consumes `CATEGORY` lives in
[functions/mod.rs](/docs/quadratic-core/src/formulas/functions/mod.rs), and
`array_mapped` — used by every `eval` here — comes from
[functions/util.rs](/docs/quadratic-core/src/formulas/functions/util.rs), built
on the elementwise `array_map` in
[ctx.rs](/docs/quadratic-core/src/formulas/ctx.rs). `PI` and the rest of the
numeric built-ins are in
[mathematics.rs](/docs/quadratic-core/src/formulas/functions/mathematics.rs);
the `to_number` coercion each closure calls is defined on `Value` in
[value.rs](/docs/quadratic-core/src/formulas/value.rs). The `eval_to_string`
and `NoGrid` helpers driving the test tables at the bottom of the file come
from [formulas/tests.rs](/docs/quadratic-core/src/formulas/tests.rs).
