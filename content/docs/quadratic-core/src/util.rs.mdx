`util` is the first module [lib.rs](/docs/quadratic-core/src/lib.rs) declares,
and it declares it with `#[macro_use]` — so everything defined here with
`macro_rules!` is visible to every later module in the crate without an
import. That is the whole reason the module exists: it holds the macros
(`jsexpr!`, `col!`, `pos!`, `impl_display!`) plus two functions that convert
between column numbers and column names.

Roughly two thirds of the file is a test module that round-trips the column
name conversion, from `A` up to `column_name(i64::MAX)`. This page walks the
code above it.

## !!steps Writing JavaScript in Rust

`jsexpr!` exists because talking to JavaScript through `wasm-bindgen` is
verbose: every property read is a `js_sys::Reflect::get` that returns a
`Result`, every call needs a bound receiver. The macro takes an expression
written in JavaScript-ish syntax and expands it into that plumbing, using `?`
on each fallible step — so, as the doc comment says, it may only be used
where `?` can propagate a `JsValue` error.

It is a token-muncher: each arm peels the leftmost piece off the input and
recurses on `$($rest:tt)*`. The two base cases end the recursion, and the
`&` / `*` arms simply pass Rust's own referencing operators through. Macro
bodies are only checked when they expand, and the parenthesis arm's `let inner
= ...` has no terminating semicolon — neither of the crate's two `jsexpr!` call
sites starts with a parenthesised group, so that arm never expands.

```rust ! util.rs
/// Recursively evaluates an expression, mimicking JavaScript syntax. Assumes
/// that `?` can throw an error of type `JsValue`.
// !mark
macro_rules! jsexpr {
    // Recursive base cases
    ($value:ident) => { $value };
    ($lit:literal) => { ::wasm_bindgen::JsValue::from($lit) };

    // Rust referencing and dereferencing
    (& $($rest:tt)*) => { &jsexpr!($($rest)*) };
    (* $($rest:tt)*) => { *jsexpr!($($rest)*) };

    // Parentheses
    (($($inner:tt)*) $($rest:tt)*) => {{
        let inner = jsexpr!($($inner)*)
        jsexpr!(inner $($rest)*)
    }};
    // ...
}
```

## !!steps Awaiting and reading properties

`.await` on a JS value means "this is a `Promise`": the arm converts it into a
`js_sys::Promise`, wraps that in a `JsFuture`, awaits it, and keeps munching
with the resolved value bound to `result`.

Dot syntax is sugar rather than a separate mechanism — `recv.foo` is rewritten
into the bracket form `recv["foo"]` by stringifying the identifier, and the
bracket arm is what actually performs the read via `js_sys::Reflect::get`.
Because both arms rebind the result to a fresh `ident`, the next recursion
matches `$recv:ident` again and the chain can continue for as long as it needs.

```rust ! util.rs
    // Await
    ($recv:ident.await $($rest:tt)*) => {{
        let result = ::wasm_bindgen_futures::JsFuture::from(::js_sys::Promise::from($recv)).await?;
        jsexpr!(result $($rest)*)
    }};

    // Dot syntax
    ($recv:ident.$property_name:ident $($rest:tt)*) => {{
        let property_name = ::wasm_bindgen::JsValue::from(stringify!($property_name));
        // !mark
        jsexpr!($recv[property_name] $($rest)*)
    }};

    // ...

    // Property access
    ($recv:ident[$($property_name_tok:tt)*] $($rest:tt)*) => {{
        let property_name = jsexpr!($($property_name_tok)*);
        let result = ::js_sys::Reflect::get(&$recv, &property_name)?;
        jsexpr!(result $($rest)*)
    }};
```

## !!steps Calls, one argument at a time

A bare call converts the callee to a `js_sys::Function` and invokes it with
`undefined` as the receiver; a method call first reads the property, then
invokes it with the object as the receiver. Both hand off to the same private
`@ call_internal` arms.

Those arms exist because `js_sys::Function` has no variadic call. So the macro
recurses down the argument list, `bind1`-ing one argument at a time onto the
function until none are left, and finally invokes the fully bound function with
`call0`. Three arguments become three binds and a zero-argument call.

```rust ! util.rs
    // Function call
    ($func:ident($($args_tok:tt)*) $($rest:tt)*) => {{
        let func = ::js_sys::Function::from($func);
        let result = jsexpr!(
            @ call_internal (::wasm_bindgen::JsValue::UNDEFINED)
            func($($args_tok)*)
        );
        jsexpr!(result $($rest)*)
    }};

    // Method call
    ($recv:ident[$($method_name_tok:tt)*]($($args_tok:tt)*) $($rest:tt)*) => {{
        let property = jsexpr!($recv[$($method_name_tok)*]);
        let method = ::js_sys::Function::from(property);
        let result = jsexpr!(
            @ call_internal ($recv)
            method($($args_tok)*)
        );
        jsexpr!(result $($rest)*)
    }};

    // ...

    // Function call with a specific number of arguments
    // !mark(1:4)
    (@ call_internal ($recv:expr) $func:ident($arg1:tt $(, $($rest:tt)*)?)) => {{
        let bound_function = $func.bind1(&$recv, &jsexpr!($arg1));
        jsexpr!(@ call_internal ($recv) bound_function($($($rest)*)?))
    }};
    (@ call_internal ($recv:expr) $func:ident()) => {{
        $func.call0(&$recv)?
    }};
```

## !!steps Two macros for readable tests

`col!` and `pos!` turn A1 notation into numbers at the call site, so tests can
say `col![nC]` instead of `-3` and `pos![Cn6]` instead of a `Pos` literal. Both
work by `stringify!`-ing the identifier and feeding it to a real parser —
`column_from_name` below for one, `CellRef::parse_a1` for the other — then
panicking on failure, which is exactly the behaviour you want inside a test.

They carry `#[allow(unused)]` because the non-test builds never expand them.
[tests.rs](/docs/quadratic-core/src/formulas/tests.rs) and the per-category
function tests are the heavy users.

```rust ! util.rs
/// Converts a column name to a number.
#[allow(unused)]
macro_rules! col {
    [$col_name:ident] => {
        $crate::util::column_from_name(stringify!($col_name)).expect("invalid column name")
    };
}

/// Parses a cell position in A1 notation.
#[allow(unused)]
macro_rules! pos {
    [$s:ident] => {
        $crate::formulas::CellRef::parse_a1(stringify!($s), $crate::Pos::ORIGIN)
            .expect("invalid cell reference")
            .resolve_from(crate::Pos::ORIGIN)
    };
}
```

## !!steps Column numbers to column names

The grid is infinite in all four directions, so column indices are signed.
Negative columns mirror the positive ones through `n = -(n + 1)` — column −1
becomes 0 and prints as `A`, with a literal lowercase `n` pushed on the end
(and later reversed to the front) to mark the sign.

The positive half is bijective base 26: digits are pulled off with `n % 26`,
and the `n -= 1` after each division is what makes the sequence run
`Z`, `AA`, `AB` rather than `Z`, `BA`. Digits accumulate least-significant
first, hence the `.rev()` at the end.

```rust ! util.rs
/// Returns a column's name from its number.
pub fn column_name(mut n: i64) -> String {
    let negative = n < 0;
    if negative {
        n = -(n + 1);
    }

    let mut chars = vec![];
    loop {
        let i = n % 26;
        chars.push(b"ABCDEFGHIJKLMNOPQRSTUVWXYZ"[i as usize]);
        n /= 26;
        if n <= 0 {
            break;
        }
        // !mark
        n -= 1;
    }
    if negative {
        // push byte literal of single character `n`
        chars.push(b'n');
    }

    chars.into_iter().rev().map(|c| c as char).collect()
}
```

## !!steps ...and back again

The inverse strips the optional `n` prefix, then accumulates digits
left-to-right. The inner `digit` helper only accepts uppercase `A` through `Z`,
so `column_from_name("a")` and `column_from_name("93")` return `None`, and the
first `chars.next()?` rejects an empty name (a bare `"n"` included).

Every arithmetic step is checked: `checked_add(1)`, `checked_mul(26)`,
`checked_add(digit)`. That is how a name past the end of the range returns
`None` instead of wrapping — the tests pin `"CRPXNLSKVLJFHH"` to `i64::MAX` and
`"CRPXNLSKVLJFHI"` to `None`.

```rust ! util.rs
/// Returns a column number from a name, or `None` if it is invalid or out of range.
pub fn column_from_name(mut s: &str) -> Option<i64> {
    let negative = s.starts_with('n');
    if let Some(rest) = s.strip_prefix('n') {
        s = rest;
    }

    fn digit(c: char) -> Option<i64> {
        ('A'..='Z').contains(&c).then(|| c as i64 - 'A' as i64)
    }

    let mut chars = s.chars();
    let mut ret = digit(chars.next()?)?;
    for char in chars {
        // !mark(1:4)
        ret = ret
            .checked_add(1)?
            .checked_mul(26)?
            .checked_add(digit(char)?)?;
    }

    if negative {
        ret = -ret - 1;
    }

    Some(ret)
}
```

## !!steps Listing things the way a human would

Parse errors read better as "expected a number, a string, or a cell reference"
than as a debug-printed list, so `join_with_conjunction` slice-patterns its way
through the cases: nothing, one item, two items joined by the conjunction, and
the general case where everything but the last is comma-separated and the
conjunction goes in front of the last.

Its caller is the parser's rule-alternation macro in
[parser/macros.rs](/docs/quadratic-core/src/formulas/parser/macros.rs), which
builds the "expected ..." message out of every alternative it tried.

```rust ! util.rs
/// Returns a human-friendly list of things, joined at the end by the given
/// conjuction.
pub fn join_with_conjunction(conjunction: &str, items: &[impl fmt::Display]) -> String {
    match items {
        [] => "(none)".to_string(),
        [a] => format!("{a}"),
        [a, b] => format!("{a} {conjunction} {b}"),
        // !mark
        [all_but_last @ .., z] => {
            let mut ret = all_but_last.iter().map(|x| format!("{x}, ")).join("");
            ret.push_str(conjunction);
            ret.push_str(&format!(" {z}"));
            ret
        }
    }
}
```

## !!steps Display impls and float comparison

`impl_display!` collapses a whole trait `impl` into one line: pass a type and
the arguments you would give `write!()`. The parser's grammar rules use it to
name themselves for error messages — `impl_display!(for StringLiteral, "string
literal")` and friends live in
[parser/rules/atoms.rs](/docs/quadratic-core/src/formulas/parser/rules/atoms.rs).

`assert_f64_approx_eq` is test-only (`#[cfg(test)]`) and takes the *actual*
value as a `&str`, because formula results come back as strings: it parses,
then compares against an epsilon of `0.0001` so trigonometry and statistics
tests don't fail on the last bit.

```rust ! util.rs
/// Implements `std::format::Display` for a type using arguments to `write!()`.
macro_rules! impl_display {
    ( for $typename:ty, $( $fmt_arg:expr ),+ $(,)? ) => {
        impl std::fmt::Display for $typename {
            fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
                write!(f, $( $fmt_arg ),+ )
            }
        }
    };
}

#[cfg(test)]
pub(crate) fn assert_f64_approx_eq(expected: f64, actual: &str) {
    // !mark
    const EPSILON: f64 = 0.0001;

    let actual = actual.parse::<f64>().unwrap();
    assert!(
        (expected - actual).abs() < EPSILON,
        "expected {expected} but got {actual}",
    );
}
```
