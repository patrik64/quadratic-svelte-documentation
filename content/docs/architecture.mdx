---
title: Architecture
description: How the store, the sheet model, the PixiJS renderer and the three language runtimes fit together
---

quadratic-svelte is a client-only SvelteKit app
([+layout.ts](/docs/src/routes/+layout.ts) sets `ssr = false`): the grid
renders to a canvas and all state lives in the browser. The pieces fall into
five layers.

## 1. Reactive state — `src/lib/state.svelte.ts`

[state.svelte.ts](/docs/src/lib/state.svelte.ts) is the central reactive store
— the Svelte-runes equivalent of the original Quadratic's Recoil atoms
(`gridInteractionState`, `editorInteractionState`, `gridSettings`). Cursor
position, selection, open panels, the input state and the active sheet all
live here, and every component imports from it directly.

## 2. Sheet model — `src/lib/core/`

The pure, unit-tested spreadsheet model, free of any UI or rendering concerns:

- [Sheet.ts](/docs/src/lib/core/Sheet.ts) — sparse cell/format storage plus
  the dependency edges between cells.
- [SheetController.ts](/docs/src/lib/core/SheetController.ts) —
  operation-based transactions with captured inverses; the undo/redo engine.
- [GridOffsets.ts](/docs/src/lib/core/GridOffsets.ts) — maps between cell
  coordinates and world (pixel) coordinates, with per-column widths and
  per-row heights.
- [updateCellAndDCells.ts](/docs/src/lib/core/updateCellAndDCells.ts) — the
  recompute pipeline: write cells, evaluate code cells, spill array output,
  recompute dependents transitively.
- [a1.ts](/docs/src/lib/core/a1.ts),
  [series.ts](/docs/src/lib/core/series.ts),
  [cellTextFormatter.ts](/docs/src/lib/core/cellTextFormatter.ts) — A1
  notation, fill-handle series detection, and display formatting.

## 3. Rendering — `src/lib/grid/pixi/` + `GridCanvas.svelte`

[PixiGrid.ts](/docs/src/lib/grid/pixi/PixiGrid.ts) is the PixiJS grid engine
(the port of Quadratic's `gridGL/pixiApp`): display objects persist between
frames, pan/zoom is a pure viewport transform, and layers redraw only when
their dirty flag is set. [GridHeadings.ts](/docs/src/lib/grid/pixi/GridHeadings.ts)
draws the row/column headers and
[measureText.ts](/docs/src/lib/grid/pixi/measureText.ts) handles text
measurement for cell layout.
[GridCanvas.svelte](/docs/src/lib/components/GridCanvas.svelte) mounts the
engine and feeds it input events, with keyboard handling in
[keyboard.ts](/docs/src/lib/grid/keyboard.ts).

## 4. Language runtimes

Three ways a cell can compute, all funneled through `updateCellAndDCells`:

- **Formulas** — [runFormula.ts](/docs/src/lib/formulas/runFormula.ts) is the
  glue to the Rust/WASM formula engine
  ([quadratic-core](/docs/quadratic-core/src/lib.rs)), which lexes, parses and
  evaluates spreadsheet formulas (see
  `quadratic-core/src/formulas/` for the lexer, parser, AST and the function
  library). [sheetRefs.ts](/docs/src/lib/formulas/sheetRefs.ts) resolves
  cross-sheet references.
- **JavaScript** — [javascriptRunner.ts](/docs/src/lib/javascript/javascriptRunner.ts)
  evaluates async user code: the return value becomes the cell output, arrays
  spill, ESM imports are rewritten to dynamic imports, and a returned canvas
  becomes an image on the sheet.
- **Python** — [pythonRunner.ts](/docs/src/lib/python/pythonRunner.ts) runs
  Pyodide with the `getCells` → pandas DataFrame API;
  [plotlyImage.ts](/docs/src/lib/python/plotlyImage.ts) renders Plotly and
  matplotlib charts to images.

## 5. UI shell and persistence

[+page.svelte](/docs/src/routes/+page.svelte) composes the app from the
components in `src/lib/components/` — top/bottom bars, the sheet tab bar, the
code editor, the command palette, menus and dialogs.
[gridFile.ts](/docs/src/lib/files/gridFile.ts) persists `.grid` files to
IndexedDB (with multi-file support and legacy localStorage migration), and
example grids ship in `static/examples/`, generated by
[generate-examples.mjs](/docs/scripts/generate-examples.mjs).
